## 〇、结论先行

### 这几条能直接改变本仓的做法

1. **「会话开始注入画像」是本仓唯一的结构性空白，而且可以就地实现**（BV14seb6EEVP）。
   Supermemory 把「静态层（长期稳定事实）+ 动态层（最近状态）」做成一等公民，**每次会话开始一次调用 50ms，画像直接进系统提示词**，模型连搜都不用搜。
   本仓每轮做一次 KNN 现捞，没有缓存层。**落点不是 `FIXED_CONTRACT_TEXT`**（那段文本被 sha256 + `!dynamic` 断言钉死，冻结前缀缓存，见 §6.3）——正确做法是**新开一条** `ctx.systemPrompt.context` 通道（`src/index.ts:232` 已有这个 API 在用），把画像与固定契约分开。详见 §6.3。

2. **「会话开始」不等于「第一轮」，而且 `agent/session-start` 已经不存在了**（BV14seb6EEVP × 本仓代码）。
   本仓 `injectMode=autonomous` 的会话（oneshot 长任务、子代理）无新用户消息，`autonomousInjectEverySteps`（默认 15 步）才重评一次召回；`agent/session-start` 在 DSH 0.1.6 起**已被删除**，改由 `agent/created` 承担（`src/index.ts:338-343`）。给这类会话做画像层，触发条件必须是「`agent/created` **或** 工作区首次写入后」，否则**子代理会话**（最需要画像的一类）永远拿不到画像。

3. **「时效权重」与「基准分数」在同一条链路上，任何排序改动都要重新标定绝对阈值**（BV14seb6EEVP 的「分数跟着配置走，不跟着品牌走」）。
   本仓 `gateThreshold=0.55` / `minKnnForReward=0.6` 是**绝对余弦阈值**，`adaptiveKRatio` 只在池 <5 时关闭、`selectionRecencyCap` 等权重是**相对排序分**。给低 `knn` 的老篇加任何权重，都会影响「谁进入 top-k」，**但不改变 knn 本身**——所以 `gate` 与 `minKnnForReward` 不受影响，可安全实验。

4. **多轮递归召回在本仓是可行且廉价的**（BV1es4NzREvi）。
   VCP 5.0 的「源思考链」在**同一条链里每推理一步重召回一次**（视频实说递归了五步）。本仓注入时延实测 p50 ≈ **2.9s**（见 §六），但这个成本主要在嵌入编码与联邦双请求，**不在召回本身**——`pipelineElapsedMs=5~14ms`。所以「多召回几轮」在时间上几乎是免费的，贵的是每轮都要重新嵌入。

5. **字面同义词会在语义通道里稳定漏召回，而且漏得很隐蔽**（BV1es4NzREvi：C++ 与 JS）。
   视频断言传统 RAG 处理不了「C++ 项目其实用 JS 实现」这类跨词源关联。本仓的 TagMemo 共现图是同一思路的解法，且本仓自己的 `FIXED_CONTRACT_TEXT` 已经写明「Tag 是**检索锚**」。
   **可做的事**：写日记时把「同义但不同字面」的词显式补进正文（例如把「注入时延 / inject latency / elapsedMs」写在一起），比事后调阈值便宜。

### 这几条容易读反，先泼冷水

- **VCP 5.0 视频里没有任何可用的准确数字**。全片是产品叙事（「吊打」「完爆」「地球上最强」），唯一的具体数字是「递归五步」「100 万/1000 万条知识里找出十几条」，无可复现口径。**不能拿它做验收标准。**
- **「VCP 上下文引力场」的 0.3 / 0.5 距离阈值不能直接搬进本仓**——见 §二 的换算：那几乎肯定是欧式距离，换成余弦后是 0.955 / 0.875，与本仓 0.55 / 0.6 是两个量级。直接照搬会把门控彻底放空。
- **「娜迦 3.0」的人类记忆模式是反面教材**（BV1n6gNzoECH）。它 3.0 beta 的做法是「每一个对话都会回忆」，结果 AI 回复迟滞；正式版改成事件驱动 + MCP 主动查询。**这正好是本仓要避开的形状**，但它给出的「为什么」值得记：人类回忆是有主动触发的，不是被动灌输的。

### 核心主张

VCP 5.0 把「工具协议 + 分布式网络 + 记忆系统 + 思维系统」耦合成了一个自认为超越现有 AGI 产品的整体；其中与记忆相关的部分是：**语义补网（跨词源联想）+ 瑞士轮 re-rank（大批量决赛式排序）+ 源思考链（推理与召回交替递归）**。

### 关键机制与数字

**① 语义补网（字幕：「羽翼博网 / 语义波网 / 语捕网 / 补网」，同一概念有 5 种写法）**

问题陈述（这是全片最有价值的一句）：

> 传统 RAG 可以把不同语言的**同词源**（如诗歌 poetry 系列的近义词）建立联系，但**「我这里聊的是 C++，而这个 C++ 技术在我的日记里是通过 JS 来实现的」——C++ 和 JS 是隔得非常远的词源，传统 RAG 处理不了。**

解法：预先设定「**编程语义补网**」这类概念域（向量划定的概念范围）；当系统检测到当前讨论与这个域产生接触，就激活该补网，把该域内**所有**相关 RAG 知识打捞起来。补网词表**有自学习功能**，随长期聊天自动构建。

> 对本仓的意义：这正是 TagMemo 共现图在做的事（Tag 作为检索锚，把字面不相近但在同一域内的条目带进来）。视频没有给出补网的数据结构或阈值，**不能提取实现细节**。

**② 瑞士轮 re-rank（字幕：「瑞士轮技术」「瑞士人是一个在传统的竞技比赛里面常见的一个概念」）**

- 传统 re-rank：给 5~10 条知识，和上下文比对，返回**一个排序**。
- VCP 的做法：**扩大补网范围 + 分批补网**，对多组向量知识做**轮次小组赛排位**，采取**积分制 + 积分循环排位制**，最后决出「冠军记忆 / 亚军 / 季军」。
- 声称目的：实现「真正的超大范围的多方向比对」。

**③ 源思考链（字幕：「VCP 源思考链」「VP语言思考链」「递归向量的思维系统」）**

- 每一步：**感知上下文 → 召回 → 推理 → 召回 → 推理**，反复递归。
- 视频原话：「你看他递归了**五步**」，并且每步都激活了不同的补网（编程语义网 + 莱恩哲学相关网）。
- 思考词源**也是动态向量化的**，不是民意（疑似「民营/人工」误识别）意识展现。

**④ 其他（与记忆弱相关，仅记录）**

- 符号归因收纳正则转化器：计算上下文里标点符号应该出现的位置，做归纳性挪动，让上下文「更符合 AI 的可读性而不是用户的可读性」。声称能提升注意力权重。
- 主动回忆：`deep memo` 插件，用语义算法召回**客户端原始聊天上下文文件里的原始回忆块**（即「回到原始对话文件去找」，而非只查摘要库）。
- 时间模糊：可以对「我们上周聊了什么」这类模糊时间表达做范围限定检索。
- 动态上下文：时间、天气、新闻（称聚合几百个门户网站的几千条新闻）、最新论文。

### 数字可靠性评级

**全片没有一个可复现的数字。**「递归五步」是定性描述，「100 万条 / 1000 万条知识里找出十几条」没有口径（没说 recall@k、没说多少条候选）、「远超人类」是修辞。**评级：D（宣传材料）**。

## 二、BV1SZ5U6ZEsN ｜[VCP]VCP上下文引力场—让上下文引导系统航行。

| 项 | 值 |
|---|---|
| BV 号 | BV1SZ5U6ZEsN |
| UP 主 | 红莲の狮子 |
| 时长 | 756s（12:36）｜字幕 311 条 ｜ 3778 字 |
| 出处 | `vcptoolbox.com`，同作者的机制讲解 |

### 核心主张

上下文不是「一楼一楼」按消息切，而是**按语义差分切成若干语义区**；每个语义区在向量空间是一个坐标，区与区之间算「引力」的方向与**曲率**；曲率决定某段内容在当前话题下要不要展开、折叠成一句话，还是干脆不给 AI 看。

> 作者自己强调：这个系统**没有对应的源码模块**——它是多个模块耦合之后涌现出来的，源码里查不到。

### 关键机制与数字

1. **语义分块**：不用「A 一句 B 一句」切，用**内容的语义差分/偏转**切成段落。「这一段讲了什么内容」是切分依据。
   - 例子：第一区日常问候 → 第二区今天日常 → 第三区网上信息 → 第四区 VCP 代码，是**语义分区**而不是逐条分区。
2. **向量表示**：每段在向量空间是一个**3072 维归一化矢量**；实际计算用**欧式 KNN**（视频原话「我们最后算的是欧式的 KN」）。
   > ⚠ 这句与「归一化矢量」并列时有个细节：**归一化后欧氏距离与余弦是单调等价的**（d² = 2 − 2cos），所以度量选哪个不影响排序，但**阈值的数值会完全不同**——见下。
3. **判据阈值**：
   - 距离 **≤ 0.3** → 「对 AI 显示这一段」；
   - 距离 **> 0.3** → 「跟这段话的关系不大，不显示」；
   - **0.5 附近** → 引入一句 `description` 做精细化判断；同时把这句话当**新坐标**（引入多个「负数的语义坐标」，疑为「附加/负向」语义坐标）参与控制。
4. **三大用途**：
   - **上下文折叠 V2**：话题转向代码时，把开头的问候段、聊番剧段「收纳折叠成一句话」（因为它们与当前工作语义距离远）。目的：①控制注意力 ②**大量节约 token**。
   - **工具选择预判**：算上下文与各工具的语义距离，决定 AI「该知道哪些工具、不该知道哪些」——视频称之为「预判整个上下文的 token 消耗」。
   - **`river` 语法**：把「上下文 + 上下文语义引力传递」一起传给工具。举例：图片的 base64 可以让第二个 AI 直接拿到（不用文字转述）；生图时把「现在是晚上、外面在下雨」这类背景作为语义牵引。
5. **范式定位**：作者说「浪潮系统为 AI 提供直觉联想，上下文语义引力场为 AI 提供背景环境感知」。

### ⚠ 关键换算：「0.3/0.5」搬不进本仓（这是本节最重要的一条）

视频明说用**欧式距离**、向量是**归一化**的。归一化单位向量上：

```
欧式 d = 0.3  →  cos = 1 − d²/2 = 0.9550
欧式 d = 0.5  →  cos = 1 − d²/2 = 0.8750
```

反过来，本仓的两条余弦阈值：

```
cos 0.55 (gateThreshold)  →  欧式 d = 0.9487
cos 0.60 (minKnnForReward) →  欧式 d = 0.8944
```

**结论**：VCP 的 0.3 / 0.5 与本仓的 0.55 / 0.6 **相差一个量级**，不是同一把尺子。把 0.3 直接当余弦阈值用，等于「距离 ≤ 0.3 才显示」→ 几乎什么都不显示；把 0.3 当余弦**相似度**用，等于「相似度 ≥ 0.3 就显示」→ 门控彻底放空。

> ⚠ 另有一条不确定：视频同时出现了「3072 维」与「测地线查询」（字幕「测离线查询 / 拉萨特离线系统 / 测地线」）的描述。如果实际用的是**超球面/测地距离**而非欧式，上述换算不成立。**这条待确认，标为假设。** 但无论哪种，**0.3/0.5 都不是余弦相似度**这一点是稳的。

**所以「用 VCP 的 0.3/0.5 校准本仓 Ω 阈值」这个想法在算术上不成立**——除非先确认 VCP 的度量与距离定义（视频没说距离是 1−cos、还是欧式、还是测地线）。

### 与本仓的可迁移点

| # | 点 | 判定 | 理由 |
|---|---|---|---|
| 1 | 「距离 0.3–0.5 引入 description 做二次判断」这个**分档处置**结构 | **需改造（结构可用、数值不可用）** | 本仓的 `thematic_neighbor`（Ω 低时由 structural 降级）就是「中间档」产物，但没有「中间档再做一次精细判断」这一步。**可做的实验**：在 `gateThreshold` 附近的窄带（例如 0.50–0.60）引入一次「用标题+Tag 再算一个相似度」的二次判断。**判据**：窄带内负例（本仓已有的负例校准集见 `config.ts:gateOnCurrentMessage` 注释：天气/晚饭/订票三条，w1 得分 0.4536/0.4830/0.5124）在改动后是否仍被拦下。 |
| 2 | 语义分段（而非逐句分块）用于**压缩** | **不适用（本仓不做上下文压缩）** | 本仓是 dsh 的**记忆插件**，上下文压缩由宿主（`compress` / `decompress` / `search_context`）负责，本插件拿不到压缩钩子。**但**：这套「按语义段算曲率 → 远段折叠成一句」的描述，与宿主压缩工具的 `topic + summary` 形态高度同构，值得转给宿主侧看。 |

## 三、BV14seb6EEVP ｜20岁辍学生做出 AI 记忆基准第一：Supermemory 怎么解决 AI 失忆？

| 项 | 值 |

### 核心主张

> **记忆和 RAG 是两件事。RAG 检索的是文档片段，无状态，对所有人返回一样的结果；记忆跟踪的是关于人的事实，而且事实会变。**

一句话概括解法：**记得多不如忘得干净**。

### 关键机制与数字

这是 5 个视频里**数字密度最高**的一个，且明确标了「厂商自报」的部分——下面的表把两者分开了。

**① 三个基准第一（厂商自报）**

| 基准 | 成绩 | 测什么 |
|---|---|---|
| LongMemEval | 第一名，**recall@15 = 95%** | 长期记忆与知识更新 |
| LoCoMo | 第一名 | 长对话里的事实回忆（含多条时序对抗样本） |
| ConvoMem | 第一名 | 个性化与偏好学习 |

**② 效率数字**

- 拿到 **95% 召回的同时只多花约 720 个 token** → 上下文占用压缩 **99.4%**。
- 自研 **SMFS（记忆文件系统）**，在 **xAFS 基准 110 道题**上：Claude 的 token 消耗从 **7200 万降到 2400 万，省 2/3**；Codex 上省 **1.75 倍**。

> ⚠ 这几个数字的反差极大：「720 token 换 95% 召回」和「SMFS 省 2/3 token」是**两条不同的链路**，不要混着引用。

**③ 更新事实：`dynamic dreaming`（后台重读与调和）**

- 问题：RAG 面对「3 月说住纽约 / 7 月说搬去旧金山」会把两句都检索出来，模型自己猜。
- 解法：**后一条事实直接覆盖前一条，同时保留时间线**。内部维护**时序事实图谱**，每条记忆带时间戳，会更新、扩展、被推翻。后台有个持续运行的引擎（官方叫 `dynamic dreaming`）重读文档与记忆、调和矛盾、把过期状态重写成新状态。
- 视频金句：**「记忆的难点从来不是存，是改。」**

**④ 主动遗忘：临时事实带有效期**

- 「我明天有个考试」→ 考试结束那一刻失去价值 → 给这类临时事实**加上有效期，到期自动作废**。
- 视频原话：「大多数做记忆的团队都在卷怎么记得更多，这个项目在做怎么忘得干净。」

**⑤ 主动供给：用户画像（本仓最该抄的一条）**

- 传统方案：靠**搜索**，模型每次遇到新问题现去库里查一圈，**一次查询约 300ms**，还经常查不到点子上。
- Supermemory：为**每个用户**自动维护一份画像，**分两层**：
  - **静态层**：长期稳定的事实（这个人是高级工程师、用 vim、喜欢深色模式）
  - **动态层**：最近的状态（正在做健全迁移、在调限流的 bug）
- **每次会话开始一次调用，约 50ms，画像直接注入系统提示词。模型连搜都不用搜，开口之前就已经知道你是谁。**
- 视频自己点名了质疑：「这不就是把用户数据提前缓存了吗？」——回答「**当缓存的内容是机器自己提炼和更新的**，这才是难点」。

**⑥ 透明代理（可靠性设计）**

- 请求经过 Supermemory 时，若记忆服务报错，**原始请求原封不动转发给模型提供商**——「记忆挂了，聊天不挂」。

**⑦ 工程形态**

- 一个**二进制文件**零配置本地跑；模型随便挑（OpenAI / Anthropic / Gemini / 任何兼容 OpenAI 的端点）；**embedding 默认用本地 `bge-base` 模型，不需要任何 API**。
- 彻底离线：接 **Ollama + GPT-140B**（待确认，疑为 `gpt-oss:120b` 一类）就能跑得不错。
- 数据全在**当前目录的 `supermemory` 文件夹**，备份迁移就是复制粘贴。
- 本地服务跑在 **6767 端口**，API 与云端完全一致，改一行 `baseURL` 上云。
- **MCP 服务器**暴露 **三个工具**：`memory`（存和忘）/ `recall`（查）/ `context`（会话开头注入画像）。
- 连接器：Google Drive / Gmail / Notion / OneDrive / GitHub 实时同步；PDF、图片、视频、代码文件扔进去就能搜；**代码按语法树切块**。

**⑧ 竞品对照（视频给的横向表）**

| 项目 | 路线 | 关键数字/特征 |
|---|---|---|
| Mem0（字幕「mam0」） | 抽取 + 检索；向量库加一层可选图谱 | 部署量最大；**LongMemEval 93.4%** |

3. **输入面**：竞品主要吃对话；Supermemory 直接吃文件 + 实时同步。

**⑨ 自我泼冷水（必须抄进任何引用）**

> 所有厂商的基准分数都是自爆的。Supermemory 说自己 95%、Mem0 说 93.4%、Zep 在不同口径下报过 71.2% 和 94.7%。有篇论文把各家自报数字列进同一张表；**同一套 LongMemEval，Supermemory 换三个答题模型跑出 85.2 / 84.6 / 81.6 三个分数**。结论：**分数跟着配置走，不跟着品牌走。**

所以 Supermemory 把评测工具 `memorybench` 开源——「你自己跑，用你自己的数据。选型的唯一标准是在你的真实对话历史上实测。」

**⑩ 反长上下文论**

> 窗口越大这个问题越贵，并没有变得更好。注意力是会被稀释的——从 100 万 token 里找一句三周前说过的话，和从一本书里找一个脚注差不多，而且**全部历史每次都重新计费**。

### 核心主张

一个人的桌面宠物项目，用「向量库（语义相似）+ 图数据库（联想相邻）」两层检索，做到「几周之前的记忆依然能回忆起来」。

### 关键机制与数字

**① 完整对话链路（7 步）**

```
录音(pyaudio) → 语音转文字(Whisper，98 种语言) → 检索相关记忆
  → [记忆 + 人设 + 用户问题] 打包给 GPT → GPT 回复
  → 语音合成(VITS) + 情绪识别 → 映射到 Unity Live2D 动作
```

**② 两层记忆检索（本节的唯一技术核心）**

- **第一层：向量库（Rama / Chroma？）**——把当前这句话用 `OpenAI embedding API` 表示成向量，与所有历史记忆向量算距离，取最近的。作者用「A/B/C 三张桌子」的类比讲清「向量距离 = 语义相似度」。
- **第二层：图数据库（联想）**——这是作者的原创补丁，动机说得很好：

  > 「从向量数据库里匹配出来的记忆只是**语义上**比较接近的历史记忆，但真正的人类思维都是非常跳跃的——很多时候我们回忆一件事情，会把与这件事情**相关联的其他记忆**也回忆起来，而不仅仅是语义相似的记忆。这其实就是我们人类的**联想性思考**。」

  实现：图数据库里每个节点存一条记忆，联想回忆就是「找与这条记忆**相邻**或**次相邻**的节点」。

**③ 其他工程点（都在视频里明说了，可采信）**

- **流式调用**：「不能等所有文字全部输出之后再让派蒙说话」→ 用 Python 生成器函数流式调用 GPT 接口，出一句说一句，**响应速度提升不止一倍**。
- **记忆权重（印象值）**：每条记忆有权重，加载时做**多策略排序**，不是单纯匹配向量库。
- **API Key 池轮换**：短时间请求过多会被限流 → 每次新请求换一个 key。
- 两个版本：完整版（本地 VITS 服务）/ 轻量版（线上 VITS），区别主要是响应速度。

### 数字可靠性评级

**几乎没有可复现的数字。**「几周之前的记忆仍能回忆」「响应速度提升不止一倍」「98 种语言」（Whisper 官方口径，不是实验数据）——**评级：D+**。但**机制描述诚实且自洽**，比 BV1es4NzREvi 可信。

## 五、BV1n6gNzoECH ｜可以吞并所有MCP和智能体—娜迦3.0正式版：物联网，流式TTS，人类记忆模式

| 项 | 值 |

| UP 主 | 柏斯阔落 |
| 时长 | 343s（5:43）｜字幕 135 条 ｜ 1755 字 |
| 出处 | `github.com/Xxiii8322766509/NagaAgent`，开源；「3.0 正式版仍在稳定性测试中，除 TTS 外已更新至 GitHub」 |

### 核心主张

记忆系统从「1.0 索引记忆（时间戳 + 主题索引）」→「3.0 三元组（词汇关联）」，并在 3.0 正式版把**回忆从「每个对话都回忆」改成「事件驱动 + 主动 MCP 查询」**——因为「每个对话都回忆」会让 AI 回复迟滞。

### 关键机制与数字

**① 记忆系统三个版本（作者称之为「校园索引记忆系统」，字幕也可能是「校园/校园/下缘」）**

| 版本 | 机制 | 问题 |
|---|---|---|
| 1.0 | **索引记忆**：通过**主题索引 + 时间戳**查找文件里的某一段历史上下文 | 「比较粗糙」，是大片回忆 |
| 3.0 beta | **三元组数据库**：把记忆内容做**词汇关联**，「不再是简单大片的回忆，而是具有一定的逻辑性」 | **每一个对话都会回忆 → AI 回复迟滞（反应慢）** |
| 3.0 正式版 | 日常运作靠**代码设定的提示词**；给记忆系统**增加 MCP 协议**，让 AI **主动查询记忆** | 仍然依赖底层设定，不能「成长」 |

**② 作者自己给的类比（很好用）**

> 「人类在对话过程中不会这么做——你在餐厅里点菜的时候，会因为服务员的一句『你要吃什么』然后疯狂地回忆以前听到这句话有哪些回忆吗？肯定是不会的。」
>
> 「人的回忆更多是比如聊到 [某游戏]，然后你就会**回忆带出相关的人物以及人物的符号化特征**……这其中是有一个**你主动回忆**的过程的，而不是靠**灌输**给你这些内容。」

作者举的例子里，回忆链是「聊 X → 带出相关人物 → 人物的符号化特征」，属于**联想式触发**而非全库比对。

**③ 异步思考树**

- 旧版：用户指令启动 → 对话过程中做问题评级 → 决定是否启用 → 用遗传算法/减值算法处理。**线性过程，影响对话体验**。
- 3.0：思考树**外置**，不需要指定启动、不需要等待评级，**完全不影响正常对话流程**。

**④ 其他（与记忆弱相关）**

- 多 Agent 协同：「MCP 还是太局限了，要实现复杂功能还是要依靠多个智能体的协同」——config 里同时兼容 MCP 与 agent 两种方式。
- MQTT 物联网：从 topic 取传感器信息、发布 JSON 做控制。
- 流式 TTS：把回复按词句符号切割，统一申请免费的 **Edge TTS** API 合成后顺序播放，做到「长文本低延迟」。

### 数字可靠性评级

**几乎没有数字**（只有 MCP 工具数量、QQ 群号这类）。但**问题陈述诚实**——「3.0 beta 每个对话都回忆导致迟滞」是一个真实踩过的坑，价值高于它的解法。**评级：C（问题陈述可信，解法未验证）。**

### 6.3 「主动供给」缺口的具体形状（本笔记最可执行的一条）

**现状**：只有一条投递通道——`agent/pre-step` 上每轮注入 top-k 片段。`FIXED_CONTRACT_TEXT`（`src/prompt.ts:12`）是系统提示词里的**静态**契约，经 `ctx.systemPrompt.section()` 注册（`src/index.ts:229`）。

**目标**：会话开始注入一份「工作区画像」，同时保留现有每轮召回。

**最小实现草图**（三步，都不碰内核）：

1. **画像来源**：读本桶的 `workspace.json`（已有 cwd/bucket）+ `memo_stats` 四项体检数字 + 最近 N 篇日记的标题行。**全部是库读，零嵌入**。
2. **注入时机**：`agent/created`（**不是 `agent/session-start`——该事件在 0.1.6 已被删除**，见 `src/index.ts:338-343` 的生命周期握手注释；两个名字都要挂，否则回调静默不触发）+ **工作区有新写入时**一次。⚠ 后者需要本仓已有的写路径留痕，只在真新增时刷新，不要每步刷。
3. **判据**：注入后的首个 user 轮，人工/盲判「模型是否少问了一个本可避免的问题」。可直接复用 `research/recall-effect/` 的盲判协议（原样请求 + 末尾追加一句元问题，独立模型判定）。

**⚠ 三条硬约束（不满足就不能按上面画草图——这是本节最重要的部分）**

1. **不能把画像塞进 `FIXED_CONTRACT_TEXT`。** 那段文本被**三重钉死**：`scripts/acceptance.mjs:245-249` 断言 `registered === FIXED_CONTRACT_TEXT && registered === designText && FIXED_CONTRACT_SHA256 === sha(registered)`，并额外断言 **`!dynamic`**——正则 `/\{\{|20\d\d-\d\d-\d\d|\d{2}:\d{2}/` 检测动态痕迹（`scripts/acceptance.mjs:232`）。**只要画像里出现任何日期或时刻，前缀缓存保真断言立刻红。** 画像必须走**另一条通道**（新 name 的 `systemPrompt.context` section，或注入块的独立段——后者受 `tokenBudget` 约束，见下）。
2. **画像不占 `tokenBudget` 的前提是它走 systemPrompt 通道。** 若走注入块，实测最近一次注入已经 `chars=5386`（约 2100~2200 token，`estimateTokens` = CJK×1 + 其他/4，`src/runtime.ts:186`），而生产 `tokenBudget=3500`——**还有约 1300 token 余量**，够一份紧凑画像，但要盯着别和召回抢席位。
3. **自主态会话拿不到「会话开始」的语义。** 本仓 `injectMode=autonomous` 的会话（oneshot 长任务、子代理）没有新用户消息，`agent/created` 只在实例创建时触发一次。**子代理会话恰恰是最需要画像的一类**（无历史、无用户、任务靠简报）。→ 触发条件必须是「`agent/created` **或** 工作区首次写入后」，不能只靠前者。
