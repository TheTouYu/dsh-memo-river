# 记忆系统升级方案 · 2026-10-19

> **来源**：两条独立研究线的缺口交汇
> - **A 线**（AGI 深度学习）：28 个 B 站视频 / 28.2 万字 → 行业对「记忆」的共同答案
> - **B 线**（技能自进化）：18 篇 arXiv 一手核实 → 工业界对「库维护」的量表与悬崖
>
> **本文档只写一件事**：把这两边的读数，落到 dsh-memo-river 的具体改动上。
> 每条都给：机制 / 判据 / 现状证据 / 成本 / 风险。

## 零、一句话判断

**本仓的记忆系统已经解决了「存得下、想得起」，但没解决「忘了该忘的、知道哪些真有用」。**
A 线说明行业把答案指向**分层 + 主动供给 + 主动遗忘**；B 线说明**维护侧做错比不做更糟**，且给出了不可逾越的边界。

两边的交集是一句话：**该补的是「维护侧」，而且必须带着刹车补。**

## 一、从 A 线拿到的三条（28 个视频的共同主线）

28 个视频里至少 12 个在讲同一件事：**上下文不取决于装多少，而取决于有效信息密度**。

| 机制 | 来源 | 硬数字 |
|---|---|---|
| 主动压缩 > 满了再压 | BV1qAMR6MEA4（ACP） | 常驻 10 万 vs 50–70 万 token；缓存命中 98–99% |
| 分层记忆 L0/L1 常驻、L2-L4 按需 | BV1Z7RNBmENU（GenericAgent） | 20 个技能后：OpenClaw 43000 tok / Claude Code 22000 / GenericAgent **2298** |
| 三问评估（更新/遗忘/主动供给） | BV14seb6EEVP（Supermemory） | 95% 召回只多 **720 token**；画像 50ms |

**对 A 线最重要的一次纠错，来自子代理**：VCP 的「距离 ≤0.3 显示」是**欧式距离**，归一化向量下 `d²=2−2cos`：
- 欧式 0.3 → **cos 0.9550**；欧式 0.5 → **cos 0.8750**
- 本仓 gateThreshold 0.55 → 欧式 0.9487；minKnnForReward 0.6 → 欧式 0.8944

**两者差一个量级。**「拿 VCP 的 0.3/0.5 校准我们的 Ω」这个想法在算术上不成立，已从候选中划掉。

## 二、从 B 线拿到的四条（18 篇 arXiv 的判据）

| # | 结论 | 数字 | 对我们的含义 |
|---|---|---|---|
| 1 | 自写技能默认零收益 | LLM 写 **+0.0pp** / 人策展 **+16.2pp** | 自动沉淀不是天然好事，得有验收 |
| 2 | 瓶颈在管理员不在作者 | 同模型：无治理 **+0.002** → 有治理 **+0.328** | 我们作者侧已够，管理员侧是空的 |

| 4 | 裁判把失败判成通过会毁掉统计量 | 错误率 ≥ **(1−τ)/2** 则任何样本量都退不掉 | 别用 LLM 裁判驱动淘汰 |

## 四、升级方案（五件事，按「刹车优先」排序）

### P0 · 接上 `recordHurt` 的调用点（把空传感器变成有数据的）

**为什么排第一**：它是唯一一件「已经写好 80%、差一步就有用」的事。没有它，后面所有维护侧决策都是拍脑袋。

**机制**：在注入块之后的下一轮，判定该轮是否出现**用户纠偏**，命中则对上一轮入选集记 hurt。
判据必须是 deterministic 的，不用 LLM 裁判（见 B 线结论 #4）。可用的确定性信号：
- 用户消息里出现「不对 / 错了 / 你搞错了 / 不是这样 / 重新」等纠偏词
- 用户在紧接着的下一轮撤销/反向要求（工具层面可观测）

**判据**：跑一周后 `memo_stats` 的 `hurtTotal > 0` 且 `hurtFiles/files` 有分布（不是全 0 也不是全中）。

**成本**：小（一个判定函数 + injector 一处调用）。**风险**：低（纯观测，不改召回，C3 断言守着）。

---

### P1 · 按 D 号读全文：`memo_read`（最小工具面扩展）

**为什么**：注入块给了 D 号却给不了全文，等于「给了索引不给书」。B 线 Headroom 的 CCR 第三段（retrieve）正是这个。

**机制**：新增 `memo_read { id | title, maxChars? }`，只读、不改。返回该篇完整正文 + Tag + 取代关系。
**明确不做**：不合并进 `memo_recall`（那是召回，这是寻址，混在一起会让召回语义变模糊）。

**判据**：模型拿到 D 号后，能一次调用取全文；`probe-*` 断言 `memo_read` 对不存在 id 报错而非静默空。

**成本**：小。**风险**：极低（纯读）。

---

### P2 · 注入块里的「索引层/正文层」分离（A 线分层记忆的最小落地）

**为什么**：现在注入块每条都塞 800 字正文。GenericAgent 的判据是「L1 只存标记，真需要再从 L3 拉 SOP」。
**但**——B 线有一条**反向压力测试**：SkillsBench v4 说「≤3 模块的聚焦技能优于更大包」，而粒度对比小且不确定
（GPT-5.5 +0.7pp / DeepSeek −6.7pp）。**给什么（可得性）比给多细（粒度）重要得多。**

**所以本项降级为 P2**：先做 P1（可得性），再谈分层（粒度）。

**机制**：注入块默认给「标题 + 一句话结论 + Tag」（索引层），正文改为按需 `memo_read` 拉取。
**判据**：同预算下 `direct_answer` 占比是否上升；用户/模型主动 `memo_read` 的频次是否 > 0。

**成本**：中。**风险**：中（可能让「不主动查」的会话拿到更少上下文 → 必须有开关，灰度）。

---

### P3 · 画像层：会话开始注入「这个桶是什么」（A 线主动供给）

**为什么**：Supermemory 的静态层+动态层，会话开始 50ms 注入画像，模型连搜都不用搜。

**关键约束（子代理已用代码核实）**：
- **不能塞进 `FIXED_CONTRACT_TEXT`** —— 它被 `scripts/acceptance.mjs:245-249` 三重钉死（`===FIXED_CONTRACT_TEXT` / `===designText` / `sha256` 相等），且额外断言 **`!dynamic`**（正则 `/\{\{|20\d\d-\d\d-\d\d|\d{2}:\d{2}/`）。画像里一出现日期时刻，前缀缓存断言立刻红。
- 正确落点是**新开** `ctx.systemPrompt.context` 通道（`src/index.ts:232` 已有此 API 在用）
- **`agent/session-start` 在 DSH 0.1.6 已删除**，改由 `agent/created` 承担（`src/index.ts:338-343`）。触发点必须是 `agent/created` **或**工作区首次写入后——否则**子代理会话**（无用户无历史，最需要画像的一类）永远拿不到。

**机制**：桶级 `画像.md`，静态层（项目是什么/关键决策）+ 动态层（最近在做什么），会话开始注入。
**判据**：画像注入后，首轮召回命中率 vs 对照；子代理会话能拿到画像（不是空）。

**成本**：中。**风险**：中（污染前缀缓存就退步，必须与固定契约隔离）。

---

### P4 · 维护侧治理：**只做巡检，不做自动退役**

**为什么放最后**：B 线结论 #3 是硬刹车——我们语料百级篇数、每篇召回常是个位数，
**按贡献退役几乎必然是 A4（提前退役 → −0.019，掉穿地板）**。

**机制**（只读，全部写进 `memo_patrol`）：
1. **第四类巡检：同轴顺序漂移** —— 后写篇的结论与前写篇冲突但未声明 supersede
2. **书漂移三态读数**（Library Drift 的现成诊断表）：`stagnation`（未覆盖/neverUsed）/ `bloat`（篇数增长 vs 召回质量）/ `erosion`（superseded 篇是否回升）
3. **退役前置闸打分**：对每篇给出「召回次数 / hurt 次数 / 是否够格退役」——**够格不等于执行**

**硬闸**：`召回次数 < 10` 禁止进入任何自动退役候选。这条写进代码，不写进文档。

**判据**：`memo_patrol` 能报出漂移候选；但**没有任何代码路径会自动删/降权日记**。

**成本**：中。**风险**：低（只读）。

## 五、明确不做的事（附理由，防止后人重来一遍）

| 不做 | 理由 |
|---|---|
| 用 VCP 的 0.3/0.5 校准 Ω | 欧式 vs 余弦差一个量级（0.3 欧式 ≈ 0.955 余弦） |
| 用 LLM 裁判驱动淘汰 | 失败判成通过的错误率 ≥ (1−τ)/2 时机制整体失效，且看不出来 |
| 库侧篇数硬上限（照抄 C=50） | 我们是历史事实库不是解题技能书架；宽度治理应作用于**检索侧**（k/budget），已满足 |
| 拆掉 RiverMemo 换静态技能 | Trace2Skill 的 +13.8pp 对照**明确排除 OOD**，而我们跨任务事实正是语义距离大的区域 |
| 自动批准草稿 | 全局守则第 7 条：机器触发回合的草稿一律丢弃（已两次踩坑） |

## 六、与「技能自进化」的关系（避免概念混淆）

| | 记忆河流 | 技能库 |
|---|---|---|
| 对象 | **事实陈述**（查过 X，结论 Y） | **可执行流程**（遇到 X 先 A 后 B） |
| 失效模式 | 结论过期（有 `memo_supersede` 治） | **库漂移**（无界累积 → 注入比不注入更差） |
| 量表 | 召回命中率 / 被用上比例 | +0.0pp / +16.2pp / −0.019 |

**两者共享同一个结构问题**：都有「作者侧」和「管理员侧」。
本方案只补记忆侧的管理员；技能侧的管理员（Curator）**不做**——因为技能库的篇数更少、
每条的召回次数更少，做自动退役必然踩 A4。

## 七、执行顺序与验收

```
P0 接 hurt 调用点     ──→  一周后看 hurtTotal 有数据
P1 memo_read 只读工具  ──→  probe 断言 + 真会话能按号取全文
P2 索引/正文分离       ──→  灰度开关，看 direct_answer 占比与 read 频次
P3 画像层             ──→  与固定契约隔离，子代理会话能拿到
P4 patrol 只读巡检     ──→  报候选，不自动执行
```

**每一级的验证台阶**（沿用 D10@常识库的「三级验证」）：
① 纯函数/契约 → ② 真挂载 → ③ 真会话真请求。汇报里写明验证到第几级。

## 八、诚实记账

- 本文档的 A 线数字来自 B 站 AI 字幕，有系统性专名误识别；**关键数字都已回扫原文确认存在**，但口播转述不等于论文原文（L2），只有 B 线是 L1（读过 arXiv 全文）。
- **P2 的收益是推算的，不是实测的**。「修记账口径 + 开 retrieve」的生产效果未验证。
- 本方案**没有**一项是「已经被证明能提升召回质量」的——它们是**补缺口**，不是**已知增益**。先说清楚。
