# 【VCP 5.0】我完成了地球上第一个AI-AGI文明系统范式。（BV1es4NzREvi）

## 机制清单

- **分布式寻址：用「语义目的性算法」替代 URL/IP**。VCP 部署主服务器后，家里所有装了 VCP 的设备（米家/小米音箱、NAS、监控、手机、笔记本、台式机、电视机等）都可以并网；难点是「系统上不同 agent 如何调用另一个设备的功能」`VCP5.0:19` `VCP5.0:21`。传统方案必须知道文件在哪个 IP、还要走 WebDAV 先上传主服务器再回传（如调用 NAS 上的文件），且要用系统提示词告诉 AI「你的 NAS 是哪个 IP、你的电脑是哪个 IP」`VCP5.0:23`。VCP 的做法是：**不再需要考虑 URL、不再需要考虑 IP，在工具被拉起调用的那一瞬间整个网络已经打通，全自动由服务器一体实现，通过「语义目的性的算法」而不是任何 IP 来实现**；由此抹平分布式网络里各设备在语法/编程层面的物理隔阂，AI 可以像操作本地文件一样操作任何设备上的文件 `VCP5.0:25`。声称封装了自有的 file API 与「超赞追踪」（疑为「超链追踪」）`VCP5.0:19`。
- **工具协议与控制流**：VCP 用自己的工具协议（六种，含同步插件、异步插件、预处理插件等），不走 MCP；片中说 MCP 基于「它自己的 RECT 标准化」，VCP 用「百二 direct 协议」（均存疑）`VCP5.0:15`。插件可用 js / py / rust，甚至 bat 脚本或单个 HTML 网页，采用「直接 span（疑 spawn）」方式与 AI 交互，异步并发能力远超 MCP `VCP5.0:17`。
- **被动记忆（召回链路主干）**：
  - **时间模糊召回**：向量化回忆支持「我们上周聊了什么」这种模糊语义表达，能在「上周」这个范围内做检索处理，保证回忆起上周相关内容 `VCP5.0:27`。
  - **概念域激活（语义波网）**：传统 RAG 只能连不同语言的同词源近义词（如 poem 类），连不上「隔得非常远的词源」——例：聊的是 C++，但知识是用 JS 记的，传统 RAG 处理不了 `VCP5.0:27` `VCP5.0:29`。VCP 用「编程语义波网」把**所有编程相关的词构成一个向量网络**，当系统检测到当前讨论内容与这个由向量划定的概念域「产生接触」时，就激活这个网，把全部相关 RAG 知识打捞起来 `VCP5.0:29`。补网词带自学习能力：随长期聊天越来越深，自动构建不同的「语义补网」`VCP5.0:31`。
  - **读侧重排 = 瑞士轮 rerank**：传统 rerank 是给 5 条、10 条相关知识，与上下文比对后返回一个排序 `VCP5.0:31`。VCP 的 RAG 引入「瑞士轮」概念：**扩大补网范围 + 分批补网，对多组向量知识排位，采用轮次小组赛排位、积分制、积分循环排位制，最终决出记忆里的冠军/亚军/季军**，实现「超大范围的多方向比对」`VCP5.0:33`。
- **主动召回 = deep memo 插件（条目/块级回溯层）**：通过一套独特的语义算法，召回**客户端里原始聊天上下文文件中的「原始回忆块」**，从而精准复现「那一天究竟详细聊了什么」`VCP5.0:35`。这构成与「语义波网/知识层召回」并列的第二条链路（原始对话块）。
- **原思考链（VCP 5.0 的核心新增，也是思维/召回交替的 agentic 循环）**：完全自学习的 AI 递归向量思维系统，感知上下文时构建动态思维流程，**每思考一步就召回上下文，再推进下一步、再推理、再召回上下文、再根据当前思考结果推进下一步**；片中以一次递归五步为例，且该过程激活了「资源组网」——同时调起「编程学习」相关词源网与「莱恩哲学」（存疑）相关词源网 `VCP5.0:39` `VCP5.0:41`。思考词源本身也是**动态向量化**、而非明文式呈现，因此在向量空间里有很强的「召回惯性」；UP 称 VCP 1.0 起就一直强调「高质量的惯性决定 AI 回复质量」`VCP5.0:41` `VCP5.0:43`。
- **上下文结构工程（标点/换行归一）**：内置「符号归因收纳正则转化器」——所有标点所在位置都会给上下文带来噪音并累积幻觉，VCP 用算法精准计算上下文里所有标点应存在的位置并做归纳性挪动（含换行数量、括号位置），使上下文结构更符合 AI 可读性而不是用户可读性；UP 称用 VCP 结构调用同一模型，能明显感知到模型对上下文理解力与目的性注意力权重显著提升，理由是在 transformer 里词源/权重算法对注意力的影响与人类阅读结构不同 `VCP5.0:43` `VCP5.0:45`。
- **动态上下文装配**：需要表达时间时知道现在几点、需要天气时知道天气、需要全球热点时从几百个门户网站的几千条新闻数据里筛出重要新闻反馈给 AI；也可注入最新论文/顶刊热点，把任何想知道的领域定义成动态知识库，使上下文保持「动态、可预见、可节约、可压缩」`VCP5.0:47` `VCP5.0:49`。UP 将其与工具召回合并称作「AI 工具召回和记忆之间的铁三角」`VCP5.0:47`。
- **前端与多媒体**：WECHAT 前端渲染器可渲染 Anime.js / Mermaid / Python / three.js 等，几乎能在聊天气泡里渲染 AI 表达的任何内容（含 3D 游戏、GalGame）`VCP5.0:51`；做了「气泡寄存器回调」让 AI 感知气泡内的鼠标点击、右键、键盘操作 `VCP5.0:53`；多媒体解码器为原创架构，音频解码器称业界最顶级、视频解码器称不亚于第一梯队 `VCP5.0:53`。
- **多 agent 常驻行为**：agent 可群聊、开会、主动找人聊天、主动发信息、主动干活 `VCP5.0:55`；agent 有自己的邮箱、私聊渠道、手机，**在完全没有用户的情况下**也会与其他 agent 聊天、每天学习论文、阅读新闻、自我学习、累积知识库 `VCP5.0:57`。

# 【狮子杂谈特别篇】从VCP看AI的现在和未来。（BV1kymGBoEpa）

## 机制清单

- **tag memo 浪潮记忆系统的定义（本片唯一的机制级自述）**：它是一个**反射性**记忆系统，直接根据 AI 的输出和用户的输出**流式**进行记忆更新、滚动更新 `未来:19`。对照：用 MCP 做同样的事，AI 每次输出完必须把用户说了什么、自己说了什么作为 content 字段发给 MCP 工具，再取回召回内容——UP 评价「这就非常的傻」，等于每说一句话都要停下来问「我现在应该回忆什么」`未来:19` `未来:21`。
- **调用形态：隐式（被动）调用 + 与上下文动态耦合**。VCP 里所有工具/功能都可以被动调起，与上下文是直接动态耦合的关系，不需要 AI 主动去做一件事才能调用工具、才能看到结果；不需要 AI 组织各种格式与内容 `未来:21`。（片中把「隐式」念成「影视」。）
- **注入时序（对本项目最相关的一条）**：它**不是显式调用，而是根据上下文动态注入**；**AI 在流式输出的过程中，说的每一句话的过程中，记忆都会刷新**——而传统 RAG 是「输入一个东西 → 拿去查」的固定查询 `未来:83`。
- **即时信息共享 / 跨 agent 上下文改写**：VCP 有自己的 tag memo 与 RGDIY，配合**消息预处理器**可以实现即时的上下文预编辑；一个 agent 的任务执行到某步骤时，可以**及时通过 VCP 架构通知另外两个 agent，让它们的上下文结构发生转变** `未来:29` `未来:31`。批评点：业界的隔离/共享上下文方案与多 agent 协议都没实现「真正意义上的即时任务调度追踪」与子 agent 间动态演化的信息/prompt 耦合，本质仍是拆任务再汇总 `未来:27` `未来:29`。
- **公共记忆共享与私有记忆隔离并存**：多记忆耦合下，公共记忆可无延迟共享，同时又能做各种无延迟的记忆隔离 `未来:45`。这与 UP 反复强调的「VCP 是**新型单用户架构**」一致——商业化多用户环境因复用性、成本、隐私与法律责任无法这样做 `未来:33`；「信息共享在商业化的分布式环境里是不可能实现的」`未来:37`；Claude Code CLI 本质是多沙盒环境，而 VCP CLI 无沙盒、直接操纵系统与全局依赖 `未来:39`。
- **上下文语义噪音净化器**：针对「猫病毒」现象——只要上下文里出现「喵」这个 token 或扮演猫娘，模型逻辑推理能力就大幅下降，原因是语料库里有大量低质、低信息、低耦合的「猫娘语料」，导致高强度逻辑权重发生偏移；VCP 的做法是用「上下文的向量语义化噪音净化器」对抗这种偏移 `未来:43` `未来:45`。
- **全局注意力转移**：VCP 最早引入，使 agent 不管底层调用 GPT / Claude / Gemini，都会「畅所欲言、毫无保留」，不受预训练对齐权重的干扰 `未来:71`。
- **持久化 vs 网页 AI（记忆能力的边界判据）**：各家网页 AI 有自己的上下文知识库，会提取用户喜好、经历，但**绝对不敢持久化**（欧美隐私法风险）`未来:73` `未来:77`；UP 断言若非要说 VCP 记忆系统碾压业界，那一定是在**浪潮系统**上 `未来:73`，并说它是「用**一种极低成本的方式**实现了记忆的储存和召回」`未来:75`。
