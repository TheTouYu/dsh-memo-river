## 一、Horizon 模型 / 宏递归模型（BV17qtGz9EfY）

### 机制清单

- **架构定位：既不是 RNN/CNN，也不是 transformer，也不是 Gemini 那种混合架构**；UP 判断它用的是「宏递归」架构（ASR 念成「红递归」，H59 首次出现并把「红递归」当待解释术语，H73/H75 又念成「宏递归」——同一概念，无第三种含义）`Horizon:11` `Horizon:59` `Horizon:73` `Horizon:75`。
- **宏递归的机制内核（UP 的亲口类比，非论文口径）**：人类「不是逐句局部推理，而是整体神经元在拓扑上被一次扫描」——大脑是层层叠起来的「黄油／聚合体」融合成复杂拓扑结构，像一面具有特殊折射率的镜子，一道光照进去就**折射出信息的投影**，再由「傅立叶变换器」把投影转成语言词元。`Horizon:61` `Horizon:63` `Horizon:65`。Horizon 被判断为同构：信息被抽象化后**进入整体宏模型**，由一个函数的整体抽象化直接输出，交由解码器解码。`Horizon:67` `Horizon:69`。
- **输入输出契约**：输入=被抽象化（向量维度化）的上下文/信息；输出=整体抽象化后的信息，再交解码器。它不是 transformer 那样用并行线性函数做高维运算推理 `Horizon:67` `Horizon:69`。**上下文与输出解耦**：UP 表述为「他的输出跟上下文是无关的」「他的注意力也不存在一个所谓上下文的注意力」「注意力也不会丢失」`Horizon:83` `Horizon:107`。
- **算力特性**：随着上下文增长，**计算推理量／算力不增加**，注意力不丢失，可完整精准地理解上下文 `Horizon:33` `Horizon:107`。这是与 transformer 的「注意力系数化（远端模糊）」相对立的卖点 `Horizon:25` `Horizon:83`。
- **vs MoE 的关键差异**：MoE 的「知识库」依赖**上下文激活**（部分激活参数量），Horizon 的知识与经验是**一次直接的红投影（宏投影）**——输出内容基于它「所有知道的一切信息」的具象化投影，而非按上下文激活参数子集 `Horizon:75` `Horizon:137`。
- **「自知（ASR：制止／质子）」能力**：Horizon 能理解「我是一个 AI 模型，上下文只不过是上下文而已，上下文不是我」，因此**用户手动编辑/篡改上下文，模型知道被改过**；UP 说这靠「自纠错的编码」实现，但明确表示不展开 `Horizon:71` `Horizon:73`。对比：猫分不清「我是我你是你」，狗可以 `Horizon:71`。
- **推理架构**：自带 reasoning 架构，「在阿尔法里面」思维链是一个可协调（可干预）的过程 `Horizon:69`。
- **生产用法（UP 自己的工程实践）**：`mix flat` 项目——**Horizon 负责「想」，Gemini 或 Claude 负责「输出/写」**，以规避 Horizon 的笔误；UP 自称这些天编程就是这么干，代码质量大幅提升 `Horizon:89`。Horizon 不适合单独上手，必须「配一个下手」，即团队化/公司化干活 `Horizon:137`。
- **与记忆/RAG 的关系**：UP 只说它「能完整精准地理解上下文，尤其是你给他提供的**知识库、记忆库、反思库**里的经验主义内容，对其运用远超其他模型」，在私有生产性角色/系统性决策领域形成断崖式领先 `Horizon:107`。**本片未涉及任何 RAG 检索算法、索引、召回链路的内部机制**；「知识库」在此指的是**喂进上下文的记忆/反思语料**，不是寻址算法 `Horizon:107` `Horizon:137`。
- **模型来源推断（属推断，非事实）**：真多模态全球仅四家（豆包、法国 Mistral 的 Pixtral/PP 系列、GPT、Gemini），故 Horizon 必出自其一是 UP 的推理链 `Horizon:49` `Horizon:51` `Horizon:53`；排除 Mistral 与 Google（后者离不开 TPU 上的 Gemini 内部顶层）`Horizon:55`；在字节与 OpenAI 之间偏向 OpenAI，理由是 GPT 在 diffusion 与多路线探索论文的**数量与含金量明显更多** `Horizon:57` `Horizon:59`。GPT-5 被官方定义为**混合多模型的通用打包服务层，按需求调用 GPT-4.1/4.5/O3/O4 等，不是具体模型**；Horizon 可能是 GPT-5 的一部分 `Horizon:93` `Horizon:95`。

### 数字与判据

- Horizon 参数量 UP 估**1~30B**；并强调非 transformer 参数量「不能起直观参考价值」`Horizon:67`。

## 二、VCP 知识库系统（BV1YgnWzxENL）

### 机制清单

- **系统定位**：VCP 5.0 前后端数据库彻底重构，**所有数据库架构、访问架构、数据处理模式、全部算法均为 VCP 原创** `前瞻:11`。
- **写入侧演进链**：VCP 1.0 `dailynote write` 写日记 → **1.1 引入 tag 系统**：写完日记自动打 tag，**tag 使日记自动分类进入不同文件夹**（即 file↔tag 的归属链）；日记带署名 + 时间戳 `前瞻:15` `前瞻:17`。
- **日记本（工作日记）机制**：AI 自建工作日记本并**取名**（如「VCP 音频解码器开发流程日记本」），把**占位符分享给其它 agent**，多 agent 通过日记本实时掌握进度、暴露端口，从而无需互相读代码即可对接——UP 称这是多 agent 异步编程的关键功能；工作日记可创建也可销毁 `前瞻:17` `前瞻:19`。
- **update / 合并 / 删除**：`dailynote editor` 的 update 可基于当前对话改写刚写的日记，也可基于今天的聊天去 update 以往某一条日记；日记非固有物，可被后续所有 agent 行动编辑、删除，或**多条合并成一条**——UP 强调这是**原子化操作（一次只作用于一条日记）** `前瞻:21` `前瞻:23`。
- **批处理层**：`dailynote manager` 插件按整本日记或指定时间段（例：2025 年 1~3 月）批处理，可对每条日记**并发异步操作与输出**；UP 明确不推荐 agent 自己跑大规模批处理（易幻觉），改由内置「**记忆大师**」agent 执行 `前瞻:23` `前瞻:25` `前瞻:27`。
- **记忆大师 + deep memo**：记忆大师带可回退操作与自己的**镜像库**，可调用 `deep memo`（深度回忆插件）从过往**聊天历史上下文**里做模糊搜索 + 快捷搜索（UP 口播「会计搜索」=快捷搜索），实现误删日记本的整本复原；实测**约 2 分钟找回**被误删的 agent 日记本；由此补齐抗崩溃、自动备份、自动镜像、自动镜像修复 `前瞻:27` `前瞻:29` `前瞻:31`。
- **索引层：HNSW + 自创寻道算法**。库本身用 **HNSW**（适用区间 1 万 ~ 1 亿条；超过 1 亿~百亿应换 IVFPQ/「ISW」类，本系统不考虑）；但**没有使用 HNSW 自带的近似最近邻算法**，改用自创的「数级轮级寻道」算法，并加了**寻道自学习**：每次搜索后分析记录「用户聊天记录 ↔ 知识库」之间的模糊对应关系，**建立热道与冷道**并改变渠道加载顺序，使下一次搜索更准更快 `前瞻:31` `前瞻:33` `前瞻:35`。
- **原子级对应 + 缓存层**：agent 知识库与其背后的**抽象多维向量矩阵**之间用**哈希值 + MD5 的纯原子级对应**，两边完全同步，并有多层级镜像与缓存；使用 lazy loading + **LRU**，全部加载走 **worker 线程**独立加载（规避 Node.js 单线程同步循环卡顿），把异步任务分发出去 `前瞻:35` `前瞻:37`。
- **召回链路（树状 RAG，共四种日记本形态）**：

### 与残差金字塔 / 读侧选择的关系

- **残差金字塔：无关（本片未涉及）**。全片无残差、正交/Gram-Schmidt、金字塔、能量截断、90% 能量、新颖度、覆盖率的任何表述（逐行核验命中 0）。`前瞻` 篇的「原子」在本片是**原子级（atomic，指操作粒度/对应关系的不可分性）**，如 `前瞻:23` `前瞻:35` `前瞻:37` `前瞻:47`，与「原子正交/正交化」无关，属同形异义。
- **读侧候选选择/去重：间接相关，且有三点可借鉴**：
  1. **动态 K（每层分叉宽度自适应）** `前瞻:43` `前瞻:45` —— 我们的读侧候选数目前是固定 K，这里是「按用户发言复杂度 + 概念宽泛度」算出一个 K，还允许用户在日记本标记上写权重乘子覆盖（`1.5`）。对读侧选择的价值：**K 从常量变成输入的函数**，且带显式人工 override 通道。
  2. **检索后时间范围合并（merge）** `前瞻:63` —— 这是全片唯一与「候选去重/归并」形态一致的机制：多条时间语义命中先合并区间再去多库检索，避免同一时段被重复检索。对我们的读侧去重：可对应「同源候选按区间/簇归并后再生效」。
  3. **语义网（词元组域 + 重叠激活）** `前瞻:53` `前瞻:55` `前瞻:57` —— 把一个语义簇的向量「圈成一个固定域」，用**域重叠**而非单点相似度作为激活判据。这比逐条 KNN 更像「簇级判别」，与我们「读侧先判簇再选代表」的思路同族；但本片**没有**给出任何簇内去重/代表选择/覆盖率计算的算法，只有「激活即撒网捞起」的粗粒度描述。
  4. **寻道自学习 / 热道冷道** `前瞻:35` `前瞻:59` —— 是对**检索路径**而非候选集本身的自适应：按历史「聊天↔知识库」对应关系改变渠道加载顺序。可类比为「hot path 预取」，与残差金字塔无交集，但对我们「读侧缓存/预取」有参考。
- **无重排机制**：全片**没有** rerank、cross-encoder、分数重排的任何描述；「权重」只作用于 K 值偏向与阈值 `前瞻:45` `前瞻:59`。读侧排序实际上依赖 HNSW 最近相似度 + 动态 K + 权重偏向三层，没有独立重排阶段 `前瞻:41` `前瞻:45` `前瞻:59`。
