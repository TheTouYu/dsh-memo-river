## 一、算法演进主线（作者自述，带出处）

- **V2**：共现矩阵（口播「共同矩阵/共线矩阵/贡献矩阵」）。假设「tag 从左往右的顺序本身具备内在的语义逻辑动力学关系」，对顺序做梯度下降预分权重 → 构巨大 tag 网络 → 上下文先 KNN 抓相关 tag，再沿加权关系往下推，把分支 tag 捞起来（**毛刺**）→ 打破同心圆、产生对比度 → 召回第三篇本来 KNN 捞不到的日记。`特篇:59-67`
- **V3**：请回信号学老祖宗 **SVD**（雷达/声纳 → 90 年代搜索引擎），对个人库做一次 SVD（100 万篇在桌面 CPU 约 10–30 分钟，之后增量），得到知识库**雷达图/蛛网**，默认 **8 轴 / 16 轴**可配，靠轴间共振规避「圆锥和球落下来的影子都是圆」的投影歧义；再配自研**残差金字塔 RP** 当扫描仪。`特篇:73-87`
  - 同代引入 **CORE tag + 能量踩尾**；**核心加权算法、正交算法、插值模块、残差金字塔、语义罗盘（EPA）** 并列为核心模块。`V3:13-15`
- **V4**：**PSR 语义偏振**——NLP 捕捉犹豫信号（虽然/但是/也许/不过/可能）→ 以此为句段做微向量化 **L2 归一** → 量化「摆动」程度 → 区分**同义反向**（「经济很好」/「经济很差」）→ 正负面消息对冲，防信息茧房。`特篇:95-101`
- **V7**：tag 神经元传播；用 CPU 为**每个用户自己的记忆库**训练一个 RNN 模型（O(N³)），服务器闲时**预计算**入 SQLite → 回忆变成查表。`V8:21-33`
- **V8（V8.1）**：「测地线原则」——质疑 KNN 两点直线不成立；对日记所有 tag 做**残差有序能分析**，用 **BFS 近似**沿直线找经过的 tag 路径 + **残差金字塔**算 tag 间能量传递与能量差 → 把直线还原成 **3072 维地形图上的测地线**。相对 V7 无额外计算，查询 0.0x ms（日志里的零点几秒是包体序列化）。`V8:37-49`
- **V8.2**：流体力学化。tag = 从左到右的河，同一 tag 跨日记 = 支流 → **河道网络**；tag 坐标归一化后算**势能差** → 用**残差金字塔正交集算法**算出每条河的地势差/起伏 → 全局地势图 + **传递顺序**。
  - 顺流借势能差推动；逆流须 tag 自带能量支付。`V8.2:13-19`
  - **钟型阻尼器**：把「非常接近」（委内瑞拉局势 vs 委内瑞拉危机，坐标差 0.02–0.05，否则「传了个寂寞」）和「非常远」（噪音）两头都屏蔽，只放行有意义的逆流传播。`V8.2:19-21`
  - 传播衰减用 **LIF 神经元放电公式**。`V8.2:27`
  - **瀑布/灵光乍现**：地势差极大处浪花溅到远方支流 = 跨河跳跃（= README 的「虫洞算法」）。`V8.2:31`
  - **朗飞结（圈 tag 语法）**：AI 说话时手动挖一条运河，下次回忆沿运河走 —— 自称「白嫖大模型算力」：本地 CPU 算不出的跨河连接让模型当场指定。`V8.2:33`
  - 终点仍是**黎曼几何测地线**：不是坐标最短距离，而是质量弯曲后沿河道流淌的能量最小距离。`V8.2:35-39`
- **V9 / V9.1 / V9.2（官网版本号 V9.2）**：把 V1–V8 统一为一个**数学场**一次性计算。
  - 关键实验：V9 对 V8 跑分 **+30% 多**（边缘噪音过滤提升好几倍）；把 V9 的 **3 个核心算法修正补丁**下放给 V8 后，差距只剩 **0.2%** → 证明「积木搭的铁皮鸭子」方向没错。`v9:17-27`
  - **V8 的测地线是取巧**：直接把 V7 tag 传递能量当测地线，不做二次计算；**V9.1 重构为真测地线**：查询是 1 个点、记忆是离散点、tag 神经元模型提供**连续地图**、每个 chunk 下的 AI 打标（file tag 链）提供**有序对称性破缺能量连线**（单链有序能量场）→ 合计**四层空间拓扑**。`v9:27-41`
  - **四大影子守护程序**评估函数：tag 质量、节点 tag 间逻辑致密性、tag 河道本身的可靠可信度。`v9:39`
  - 结论性命题：**「记忆一定存在于运动之中，绝不可能存在于静态的相对坐标距离之中」**；测地线比的是**曲线形状**而非距离——「日本大米贵」↔「菜店烤鸡便宜」在核心 tag 距离上极远，但过路河道形状极似 → 高度相关。测地线跑分**高于 RERANK 模型**。`v9:45-63`
  - V9.2 主要是工程化/数据库可靠性，跑分比 V9 高好几倍。`v9:41-43`
  - V10 展望：统一场方程把「坐标」与「运动」合为一式（自比麦克斯韦统一电磁）。`v9:65`

**贯穿全部版本的第一性论点**（`特篇:43-45`）：
> 向量只能表述**静态**关系；逻辑只在句子按顺序「运动」时才存在，一旦拍平成坐标，逻辑就消失。
> 「语义的相近性不能完全代表记忆的相关性，它依旧缺乏那个逻辑的动力方向。」

## 二、残差金字塔（RP）专题：口播定义 vs 源码实证

**口播定义（V3 时代，`特篇:83-87`）**——原文：
> 「我们虽然有了雷达图，但是就缺了一个转圈圈的东西……我们实现了一个非常原创的算法**残差金字塔 RP**。
> 在残差金字塔里面我们做了什么呢：我们**直接计算查询向量和 tag 海里面每一个 tag 之间的能量差**……
> 这一个光打下去，tag 海每一个 tag 代表了一个不同的能量峰，而查询向量和 tag 海之间的所有的这些**残差毛刺**都一瞬间被这个扫描仪找到了……
> 顺藤摸瓜通过逻辑的方向看过去，就能知道哪些 tag 是噪音，而那些**看似能量很小的 tag 却是真正我们所需要的 tag**。」

口播版补充（`V3:19,29`）：残差金字塔 = 一层层的**淘金筛子**，先筛掉「大家都知道的废话」，剩下的残渣才是真正想表达的独特创意；实现抓手是**每个 tag 与上下文两个向量之间的偏角差（角偏量）**。

**源码实证（V8.2 时代，`~/app/VCPToolBox/ResidualPyramid.js`，394 行）**：
- 文件头自述：「物理优化版。基于 **Gram-Schmidt 正交化**计算**多层级语义残差**，精确分析语义能量谱。」`ResidualPyramid.js:1-4`
- 配置：`maxLevels=3`、`topK=10`、`minEnergyRatio=0.1`、`dimension=3072`。`ResidualPyramid.js:8-18`
- `analyze(queryVector)`：E₀=‖v‖² → 逐层 `tagIndex.search(currentResidual, topK)` → 把该层 top-K tag 张成子空间、算 `_computeOrthogonalProjection` 并扣除 → 残差能量/E₀ < 0.1 时停。`ResidualPyramid.js:25-113,128`
- 输出：`levels[]` / `totalExplainedEnergy`（0~1）/ `finalResidual` / `features`（新颖度、覆盖率）。`ResidualPyramid.js:29-35,317`
- 另有 `_computeHandshakes` + `_analyzeHandshakes`（tag 两两「握手」关系）——对应口播里「能量差/残差毛刺扫描」那一半。`ResidualPyramid.js:213,271`
- 底层投影/握手有原生快路径：`tagIndex.computeOrthogonalProjection` / `computeHandshakes`（napi-rs，上游 `rust-vexus-lite`）。`ResidualPyramid.js:133,218`
- **模块是演进的同一件**：V3 口播强调「能量差扫描」，现行源码强调「Gram-Schmidt 多层残差 + 90% 能量截断」，两者在同文件内共存（analyze 内既做金字塔也做 handshake）。

## 三、对接 HANDOFF 开放问题（逐条给证据，不代替用户拍板）

**Q4「ResidualPyramid 在 VCP 是生产接线还是实验田」——已取证：生产接线。**
- `TagMemoEngine.js:644` 在引擎初始化里 `new ResidualPyramid(this.tagIndex, this.db, {dimension})`；
- `TagMemoEngine.js:994` 在每轮查询主链路上 `const pyramid = this.residualPyramid.analyze(originalFloat32)`，紧接 `[3] 动态调整策略`；
- 主链路顺序是 `[1] EPA 分析（逻辑深度与共振）→ [2] 残差金字塔分析（新颖度与覆盖率，90% 能量截断）→ [3] 调策略`。`TagMemoEngine.js:990-1000`
- 冷启动注释打的是 **V8.2-γ** 标记，说明仍在活跃维护。`TagMemoEngine.js:648-660`

**Q1「残差在哪个向量空间算」——作者口径是「查询向量 ↔ tag 海」，不是条目空间。**
- 口播：「直接计算**查询向量**和 **tag 海**里面每一个 tag 之间的能量差」`特篇:83-85`；
- 源码：`tagIndex.search(currentResidual, topK)` —— 残差向量本身去查 **tag 索引**，投影基底是**每层 top-K tag 张成的局部子空间**。`ResidualPyramid.js:48-80,128`
- 即 VCP 用它回答的是「**这条查询有多少是 tag 海已经解释过的**」（新颖度/覆盖率），**不是**「已选候选条目之间是否重复」。
- ⚠️ 因此 HANDOFF 火花 1（读侧·残差选择：选第 1 名 → 投影掉 → 在剩余候选残差里选下一个）是把该机制**从 tag 空间迁移到条目空间**的再设计，VCP 没有现成对应物——这是一个**新增量**，不是照抄。

**Q3「EPA 的 64 维正交基能不能直接当投影基底」——两者是不同用途的正交基。**
- EPA：`maxBasisDim=64`、`clusterCount=64`、`dimension=3072`、`strictOrthogonalization=true`；实现是**加权 PCA（先去中心化再加权）→ Power Iteration + 对既有基做 Gram-Schmidt 再正交**，基向量可落盘（base64 快照）。`EPAModule.js:11-15,57-61,547-655,699-726`
- 性质：**全局 / 离线可预算 / 簇级**（tag 簇的主轴），口播称「雷达图」，用途是「你在哪个世界」+ 逻辑深度 + 跨域共振。`v9:39`、`特篇:77-81`
- RP：**局部 / 在线 / 逐层 top-K tag 张成**，用途是「这条查询还剩多少没被解释」。
- 结论倾向：EPA 的 64 轴给的是**方向/世界**，RP 给的是**已解释能量**；做读侧残差选择时，RP 的结构（对已选项张成的子空间做正交扣除、迭代）比 EPA 的 64 轴更贴形。**但这仍是设计判断，留给你拍板。**

**Q2「与 topology_v3 打分怎么融合还是替换」——视频没直接回答**（口播是 VCP 自家 TagMemoEngine 口径，不涉及本仓 reimpl 的打分器）。可用的旁证只有作者的一句价值判断：「RERANK 不可靠——不能以绝对的相似性代替绝对的逻辑相关性」，以及 v9 声称测地线跑分**高于 RERANK**。`特篇:51`、`v9:47`

**Q5「三个火花一次全上还是先单点」——视频无对应内容**，属本仓工程决策。

三条决定性取证：

1. **RP 的官方定义与伪代码**：`MEMORY_SYSTEM.md:390-448` ——「残差金字塔是浪潮算法的"数学心脏"，负责语义能量的精细拆解」；`_computeOrthogonalProjection` 用 **Modified Gram-Schmidt**（注释「数值更稳定」），核心行 `v = v - <v,u_j>·u_j`，系数取 `|coeff|`，残差 `R = vector - P`。三段职责：多级剥离 / **微弱信号捕获**（对残差向量递归搜索，捕捉被宏观概念掩盖的微弱语义信号）/ 相干性分析。
