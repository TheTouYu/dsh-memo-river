## 二、六个根因

- **R1 共享工作树互踩 → 隔离取证税（≈3h）**：六代理同树在途编辑交叉污染 acceptance 结果，受影响的每个代理各自做 worktree 克隆 / HEAD-only 复跑 / stash 双盲归因来自证清白（worktree 提及 49/13/39/17 次、stash 13/6/1/7 次）。这是最大的浪费：互踩不是 bug，是共享树的必然，每个代理都付一遍取证税。
- **R2 flock 全局锁串行化 build+acceptance（≈219min）**：所有代理的构建+套件（分钟级、嵌入端点依赖）在单锁上排队。
- **R3 套件重复执行**：隔离复跑 × 多套件 × 多轮（acceptance 引用最高 135 次/代理），R1 与 R6 直接放大它。
- **R4 write-nudge 轰炸子代理，提示词红线失效**：每代理收 4-15 次写入节律提醒；prompt 里「禁写生产桶」被击穿——**18 次 memo_write 调用、6 篇落河**（D66/D69/D71/D72/D73/D74，含「记忆自驱」hub Tag，推高枢纽）。又一实证：工程提醒 > 文本禁令；写侧约束必须落在配置/闸门层（票 06 的 hub-gate 正是，但需重启 DSH 才生效）。
- **R5 波次硬屏障**：04 只依赖 03、06 只依赖 02，却全体等 wave-1 最慢的 133min 代理。
- **R6 端点抖动 + SIGBUS 重试**：relayrouter 抖动使套件单跑挂多项→重跑；vexus-lite -shm 竞态 SIGBUS（已知）→复跑，都再排队锁。

## 三、改进设计（→ orchestration-skill-0916 技能票）

1. **每代理独立 git worktree**：`git worktree add` per lane，代理间树隔离零互踩 → R1 归零，树操作免锁；提交走各自分支，主代理合并队列串行 fast-forward（唯一需要锁的地方，秒级）。
2. **套件分道**：代理只跑自己道的 acceptance + 自己改动的冒烟；合并态由主代理一次性全量回归（R2/R3 大幅压缩）。
3. **写侧由配置保证**：短命代理免 nudge（或 hub-gate enforce），不信 prompt 禁令（R4）。
4. **依赖驱动调度**：04 在 03 done 即启动、06 在 02 done 即启动，不做波次屏障（R5）。
5. **上下文最小化**：COMMON 块瘦身、结构化回收、结果只走 schema。
6. **DSH 侧上游候选**（ticket 02）：workflow 原生支持 per-agent worktree、短命代理 nudge 豁免配置、依赖图调度原语。

**预期**：R1(≈3h)+R2(219min) 大部分消除，同规模工作流墙钟 2.9h → <1h。
