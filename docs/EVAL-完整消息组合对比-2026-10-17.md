# EVAL：两会话完整消息组合 → 模型效果对比（2026-10-17）

> 研究问题（用户令）：不限于注入消息，看**完整消息组合**（含用户消息）如何影响两会话模型效果。
> 方法：/tmp/ctx.py 四模式解析器（dump/turns/ctx/human）+ 41 条真人消息全读 + 12 个关键转折点上下文重建（±8~10 条）+ 压缩-用户消息交叉量化。
> 证据：session-7ebcf56f（长跑 10h，1165 步/331 user 消息/25 压缩）+ session-b96dea52（交互 2.5h，423 步/167 user 消息/5 压缩）。

## 一、消息构成全景：真人声音占 0.5%

| 维度 | 长会话 7ebcf56f | 短会话 b96dea52 |
|---|---|---|
| 真人消息 | 26 条 / **2,291B** | 15 条 / **1,244B** |
| 召回注入 | 177KB（206 条） | 64KB（68 条） |
| 催写+nudge | 34.6KB | 18KB |
| pre-turn 注入 | 254.8KB | 163.4KB |
| 真人占比 | ≈0.5% | ≈0.5% |
| 用户介入密度 | 2.6 条/h | 6 条/h |
| 压缩次数 | 25 | 5 |

两会话真人占比相同（0.5%）——但效果天差地别，**说明占比本身不是决定变量**（见第五节）。

## 二、用户消息的两种命运：原话存活时间量化

每条真人消息 → 下一次覆盖它的压缩，间隔（分钟）：

- **长会话**（26 条）：中位 ~11 分钟。最快 0-1 分钟（seq 6778 11:53 批评→11:54 被压；seq 4756 复盘指令→1 分钟被压）；最慢 45 分钟。**12:47 之后 7 条从未被压**。
- **短会话**（15 条）：前 8 条中位 ~3 分钟；**16:05 之后 7 条从未被压**。

实证链：07:06:33 模型为复盘需要 03:35 的批评原话，只能 `search_context "你看，你又缺少探索就定目标"` 从压缩块考古（seq 4769）——**3.5 小时前的用户原话已不在可见上下文**。13:15 用户被迫手动调 /context-loss-recovery，本质是「加载所有系统提示+对照记忆」的人工补偿。

**两个「从未被压」段恰是两会话协作质量最高的段**（长会话尾声诊断链 12:47-13:30、短会话 GLM 调度段 16:05-16:42）——用户原话可见性与协作质量强相关。

## 五、同因异果的机制解释

同样的注入洪水（短会话 2.5h 吃下长会话 2/3 注入量），为什么短会话指令一次生效、长会话批评要说两次？

- **变量 A：指令类型**。短会话=动作指令（画 HTML/造工具/换提示词），可执行路径明确，秒级落地；长会话=行为模式纠正（别信脚本/要留证据），模型需自找落地形式，找到 ys-preflight 用了 2.5h。**纠正类反馈的生效延迟=找到工具化形式的延迟**。
- **变量 B：反馈密度**。短会话 6 条/h，模型处于「等待反馈」回路中，每条消息都是下一动作的路标；长会话自主态数小时无人类信号（03:52-08:47 仅系统提示通道），批评到达时模型带自主惯性，需先刹车再转向。
- **变量 C：批评通道质量**。长会话 14 条「系统提示：」来自游戏评测通道，**精准踩行为节点**（放弃汇报后 2 分钟、弯路中、时间占比统计），但模型对它的响应仍优于对注入——证明真人/准真人消息的注意力优先级压倒一切注入。
- **注入的害处不在淹没用户消息，在间接损耗**：①压缩泵 25 次——用户原话中位 11 分钟进压缩块，逐字原文消失（靠摘要转述，质量随机）；②挤占预算让模型频繁压缩；③催写误报把「系统注入量」当「未写产出」，训练模型无视提醒。

## 六、对记忆系统的设计启示（回灌 PLAN 的候选）

1. **压缩摘要必须优先保留用户原话**（现在是模型自由发挥）：批评/裁决类 user 消息应作为 protected content 或强制进摘要原文。判据：压缩后 `search_context 用户原话` 0 命中=摘要丢失。
2. **批评到达时的「批评史召回」**：recall-inject 同秒到达的总是语义相关条目（D227/D295/D185），从未是「同类批评历史」——若批评消息能触发召回该批评的既往版本（D310 类），可能第一次就完成沉淀，省掉第二次批评。落点：injector 对 user 消息做批评分类 → recall query 加「本批评的同类历史」。
3. **教训工具化空窗 2.5h**：批评→行为改变秒级，→资产化小时级。催写系统只催「写日记」，不催「把教训做成工具/检查项」。候选：write-nudge 文案在检测到「承认批评」pattern 后追加「该教训的工具化落点是？」。
4. **短会话的「等待反馈」节奏**：高密度反馈下模型表现最好（零复发）。这是用户侧策略，但系统可配合：交互态注入应更轻（短会话 pre-turn 163K 对 15 条 1.2K 真人消息仍是 130:1 的噪声比）。
