## 2. 长期三变量（为什么长期视角会改变优先级）

| 尺度 | 主要矛盾 | 该投的地方 |
|---|---|---|
| 一场会话（小时） | 把已经买过的东西又买一遍 | **去重**（本刀） |
| 几个月 | 库长大了，**陈旧结论被当成事实注入** | 语料**有效性**（G3） |
| 一年以上 | **坏了你不知道**（静默失忆、无人报警） | 可观测性（引用闭环） |

本仓实测（取自 HANDOFF 与 D214/D106，均为生产数据）：
- 单次被动召回注入 p50 **2986** token / p90 4346 / max 5074，上限 3500 → **常年贴着上限灌满**；
- 全会话注入 ≈ **129K** token，**注入 : 用户真话 = 76 : 1**；
- 一场会话里同 3 条记忆被注 **9 次**（HANDOFF）；
- 288 条被预算丢弃；
- 注入后被引用的比例**只手工测过一次**（D106：10 分钟窗内 66%）——没有常驻仪表。

**判断**：记忆系统的天花板不是算法，是**写进去的东西**。读出再聪明也读不出库里没有的；库里堆满过程记录和陈旧结论时，读出越准越糟。

## 3. 分阶段路线

### 已完成 · 第一刀：条目级注入去重（G1）

**问题形状**：`dedupeSelection` 的键是**整个入选集合**。集合一变（`{A,B,C}` → `{A,B,D}`）判据立即失效，A、B 被整块重注——每条重复都是**零收益、全价成本**。

**做法**（三条口径，首版走过弯路，改过一版）：
- `src/recall.ts` 新增 `export function candidateKey(c, homeBucket?)` → `` `${c.srcBucket ?? homeBucket}:${c.id}` ``（跨桶命名空间；父桶条目在 federate 合并时才盖章，故必须以主桶名作基准）。
- 顺序 = **集合级判据 → 条目级过滤 → 渲染**。集合级先说话，`identical-selection` 这条既有可观测语义才不会被条目级吞掉。（首版把过滤放进 `recall()` 的席位分配里 → 主套件 #12 红：跳过原因被换掉了。）
- **只剔不补**：`filterLiveDuplicates(selected, liveKeys, homeBucket)` 把仍在场的条目剔出，**空出的席位不用后位候选回填**。回填会把「跳过」变成「每轮注入更弱的新条目」——总注入量不降反升，与「停止为已在眼前的东西付费」正好相反；且会改写步维刷新语义（首版回填 → 主套件 #17 红：`injectedCount` 4 ≠ 2）。真正要救的是**部分重叠**那一半：`{A,B,C}→{A,B,D}` 时只注入 D。
- **强刷越过两条去重**：`refreshDue`（压缩后 / 隔 `dedupeRefreshTurns` 回合）是显式意图，也是对「在场判据可能漏判」的兜底。
- `src/injector.ts` 新增 `export function liveInjectedKeys(rawMsgs, state)`：消息文本 sha256 反查 `state.audits[].blockHash`，命中即取该块的 `selectionKeys`。判据是**真消息在场**、不是轮数近似 → 块被压缩折走后自动允许重注（这正是 `dedupeRefreshTurns` 当初想用轮数近似的东西，现在被精确覆盖；两机制并存，强刷那条仍生效）。
- ⚠️ **必须传 `rawHistory`**（`src/injector.ts:288`）而不是白名单后的 `history`（`:291`）——`isDialogMessage` 把 `kind==='memo-river'` 的注入块整个排掉，用 `history` 会让本功能永远空集、**静默失效**。
- `InjectionAudit.selectionKeys`（`src/session.ts`）+ 审计 200 条上限；`inject.dedupeLiveEntries`（缺省 `true`，**kill-switch**）。
- 边界：全入选都在场 → `fallbackReason='all-selected-already-in-context'`（**不**进 `isRecallInfrastructureFailure`，故不发「召回未生效」通知、不污染连续失败计数）。
- 验收：`scripts/acceptance-inject-dedup.mjs` **8/8**。主判据是真 pre-step 4 轮的**跨轮不重复**不变量（实测：开 → 逐轮 `[4,5,6]/[2]/[1]/[]`、重复 0；关 → `[4,5,6]/[4,2,6]/[4,1,6]/[4,5,6]`、重复 7）。
- **首版为何被推翻**（写在这里防回退）：回填式实现让 `injectedCount` 从 2 涨到 4、并把跳过原因从 `identical-selection` 换成 `all-candidates-already-in-context`——两个主套件判据同时红，说明它改的是既有产品语义，不是单纯加了个去重。

### 已完成 · 第二刀：G3 语料有效性（superseded，2026-10-15）

**问题**：库里存的是**事件史**，模型要的是**当前状态**。**一条过期结论被当事实注入，比不注入更糟**——模型会基于一个已经不成立的世界做诊断。本桶现成病例：D208/D214 讲「3s 嵌入硬顶 → 45.3% 被动召回静默跳过」，而超时预算早已 8s、端点也已换过；今天若为「召回为什么不生效」去查河，读到的全是已废事实。

**与既有机制的分工（关键，别混）**：

| 情形 | 谁管 | 结果 |
|---|---|---|
| 内容被并入另一篇 | `memo_merge` | 源篇归档退役（行级删除）→ **不存在**过期条目 |
| 本篇要改 | `memo_update` | 原地重写（同 fileId、换 chunk）→ **不存在**过期条目 |
| **新篇推翻了旧篇的结论，两篇都留着** | **本机制** | 旧篇的**过程/教训仍有价值，结论已不是当前事实** |

**口径（2026-10-15 用户拍板）**：被动注入**不注入**该条目，并在「未注入明细」行归因 `superseded-by-D<继任>`；主动 `memo_recall` **照常返回**并标注「⚠️已被 D<n> 取代 / 已废止」。剔除责任放在**消费方**（injector），读路径 `recall()` 只盖标——否则主动查历史也看不到全貌。

**存储（本仓第一份「插件自有 schema」）**：`src/schema-local.ts` + `src/store.ts` 追加幂等 DDL。
⚠️ **不能给 `files` 加列**：`src/schema.ts` 由 `scripts/gen-schema.mjs` 从上游参考库的 `sqlite_master` **逐字**镜像（53 条，重跑即整份覆盖），在它里面加东西会被无声抹掉、也让 DESIGN.md §9 的不变量失效。自有表：

```sql
memo_supersessions(old_file_id PK, new_file_id, reason, marked_at, marked_by)  -- new IS NULL = 废止
```

**不加外键**：`store.ts` 开着 `PRAGMA foreign_keys = ON`，而 `memo_merge` 会 `DELETE FROM files` —— 引用 files 的外键会让归档直接失败。悬挂行改由「读取 JOIN files 过滤」+ 归档处 `pruneSupersessions()` 处理。

**两条硬语义（都是验收逼出来的）**：
1. **继任篇消失（如被 merge 归档）时标记必须保留**——旧篇的结论**仍然**是被取代的；清掉它 = 让过期结论重新可注入，方向正好反了。代价只是展示降级为 `superseded-by-D?`。首版 `pruneSupersessions()` 把这种情况也清了，被 S-1 抓出。
2. **两套编号必须分开**：存储用**稳定**的 `fileId`；展示用 `D<chunk id>`（`memo_recall` 的口径）。chunk id 会随 `memo_update` 改写而变，混用会让模型去错篇（D108 已记过这个双口径）。故 `RecallCandidate` 同时带 `supersededBy`(fileId) 与 `supersededByD`(每次 recall 现算的展示编号)。

**标记通道**：① `memo_write(supersedes:[D…])`（D = chunk id 或 fileId，双口径兜底；重复去重；不存在的逐条报出且不落库；自指忽略）+ 写前回注在 `knn≥0.8` 时提示「延续优先 memo_update 并入；**推翻**其结论则声明 supersedes」；② 独立工具 `memo_supersede`（标记 / 废止 `void:true` / 解除 `clear:true`；replacement 与 void 互斥）。**patrol 自动检出不落**——「推翻」比「相似」难判得多，假阳性预期高，留最后。

**只剔不补**：与第一刀一致，空出席位不回填（改席位分配会连坐自适应 K 与步维刷新的既有定标）。强刷 `refreshDue` **不**越过这一刀——「结论已过期」不会因为隔了 8 回合就重新成立（与去重相反：那里的强刷理由是在场判据可能漏判）。
**观测**：`inject` 行加 `superseded=N supersededIds=…`（与 `deduped=` 分开计数，便于分别定标）。
**验收**：`scripts/acceptance-supersede.mjs` **7/7**（S-1 存储语义 / S-2 召回盖标+负对照 / S-3 真 pre-step 剔除与归因 / S-4 主动照返带标 / S-5 写入通道 / S-6 工具全分支 / S-7 纯函数）。

### 最后 · G4 注入按需预算

**现状**：`src/config.ts:231` 的 `dynamicK` 缺省 `1`、`src/recall.ts:264` 只当静态倍率用，生产预设（`~/.dsh/preset-bundles/river-acp/cordis.patch.yml` 只设 `k:3 / tokenBudget:3500 / gate:true / gateOnCurrentMessage:true / mode:topology_v3`）根本没设它——banner 里那句 **「动态K×1」是常量，不是动态**。而**自适应 K 的驱动量是「候选池多大」**，与「这一轮用户需要多少记忆」无关：**位置是对的，传感器接错了**。
**方向**：把驱动量换成请求侧信号（用户消息复杂度 / Ω 泛函 / EPA 逻辑深度），并让 `tokenBudget` 随之伸缩。上游 VCP 的做法可参照但**未发货**（口播：「发言复杂度 × 概念宽泛度」经正余弦/傅立叶变换得 K=5/7/9；`BV1YgnWzxENL` 前瞻篇）。
**依赖**：需要 G1 的干净注入量与「注入→引用」常驻仪表（否则调参是盲调）。

## 4. 明确不做

- **不追 VCP 的版本号**（V9.1→V9.2→V10）。它在解「百万级图上的召回精度」，我们在解「预算分配 + 语料腐化」——不是同一个问题。
- **不再加打分维度**。现有 EPA + 残差金字塔 + topology_v3 + gate + tie-breaker 已五层，再加一层，出了效果无法归因。
- **不把「召回准确率」当核心 KPI**。D106 的 66% 已经说明真正的痛是重复注入、陈旧结论、静默失败，不是「没召回到」。
- **不引入残差投影**（火花①/②的"真身"）——等 G1 的真实数字说话。上游取证见 `research/vcp-algorithm/知识提炼.md`：RP 是生产接线，但它算的是「查询向量 ↔ tag 海」（新颖度/覆盖率），**不是**候选之间的去重；V9.1 的节点级「内生残差」也只用作**锚增益**（加权），不是过滤。故火花①②是**迁移到条目空间的新增量**，不是照抄。
