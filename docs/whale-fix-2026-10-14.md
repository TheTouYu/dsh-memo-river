# emb-cache 内存鲸鱼修复 · 验证报告（2026-10-14）

> 定谳见 dsh-plugins 桶日记 D98；修复提交 `5e85fda`。判据来源：D98 实测 + 用户验收口径
> （「对 genshin 桶真发一次 memo_write，0.5s 采样 RSS 峰值增量 <50MB、无秒级事件循环停顿」）。

## 一、病根（一句话）

`EmbedClient` 构造时整读 `emb-cache.json`、任何新增嵌入后 `writeJsonSafe` **全量同步重写**：
genshin 桶 116MB/1764 条（活 chunk 仅 184）单周期 read+parse+stringify = **573MB 峰值、1.16s
同步 CPU**；`writeFileSync` 冻结事件循环 → WS 心跳超时 → 在飞回合被打断；跨桶并行叠加 →
12:42 KILL 3G / 13:40 ABRT 2.5G / 14:25 ABRT 2.6G。

## 二、改动（四件，按序）

| # | 改动 | 落点 |
|---|---|---|
| 1 清淤 | 全库逐出孤儿键（keep = `chunks.content ∪ tags.name`）+ 落二进制 | `scripts/compact-emb-cache.mjs`（新） |
| 2 止血 | 落盘去抖 2s + `fs.promises` append（不再 writeFileSync 全量） | `src/emb-cache.ts`（新） |
| 3 根治 | 二进制追加式记录日志：`'MREC'\|v\|dim\|reserved` 头 + `keyLen\|vecLen\|key\|Float32LE×dim`；Float32Array 常驻；48MB 预算 LRU 逐出；死记录过半后台压实 | `src/emb-cache.ts` + `src/embed.ts` |
| 4 退避 | 嵌入端点连败 3 次跳闸，窗口内调用**立即失败**（不再持 dbGate 等超时），窗口翻倍封顶 5min，`EMB_BREAKER=0` 可关 | `src/embed.ts` |

透明迁移：首次载入无 `.bin` 而有 `.json` → 流式切片解析（峰值≈文件字节，无 stringify 第二份）→ 落 `.bin` → 原文件改名 `.bak` 留证。截断/畸形文件自愈（截到有效长度 / 改名留证重建）。
