## 6. 文件命名规范（从现有文件反推，非发明）

现有 19 份文件呈现稳定规律：

1. **类型前缀大写 + 连字符**：`QUICKSTART` / `ADR` / `BUG` / `DEBUG` / `EVAL` / `GUIDE` / `PLAN` / `SPEC` — 前缀即文档类型，一眼分组。
2. **事件性文档带日期，常青文档不带**：
   - 一次性事件（调试/修复/评估报告/单版规划）带 `YYYY-MM-DD`：`DEBUG-inject-latency-2026-10-15.md`、`whale-fix-2026-10-14.md`、`PLAN-2026-10-15-记忆系统长期路线.md`、`SPEC-2026-10-15-…md`、`EVAL-单会话深评-…`（EVAL 例外：主题代替日期，主题词本身含时间性）。
   - 常青文档（入口/手册/决策记录）不带日期：`QUICKSTART.md`、`EVAL-生产评估-runbook.md`、`ADR-暗会话记忆覆盖.md`、`GUIDE-未命名存量修复.md`。
3. **BUG 用月日编号**：`BUG-MMDD-英文短横线短语.md`（0930/1003/1014），主题用英文短语。
4. **文件名可含中文**，且中文主题常见（PLAN/SPEC/ADR/EVAL 多份）；标识部分中英混排是常态。
5. **日期 = 事件日期**（非最后编辑日期）：`embed-latency-2026-10-14.md` 首测 10-14、内容 10-15 重测，文件名未改——重排时间线时以 mtime 与文内声明为准。
6. **数据目录小写复数**：`eval-baselines/` 存按日期命名的 JSON（`YYYY-MM-DD.json`）。
7. 历史遗留的小写起头名（`embed-latency…` / `local-embed…` / `whale-fix…`）出现在早期（10-14/10-15 之前无前缀惯例期）；此后新增事件文档已统一带 `DEBUG-` 类前缀（如 `DEBUG-inject-latency-2026-10-15.md`）。**新文档建议：类型前缀 + 日期 + 主题**。

> 本 INDEX 自身是常青入口，不带日期；状态列基于 2026-10-15 的仓库实况，重大取代关系发生后请更新 §2/§3。
