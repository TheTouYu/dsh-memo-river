# 存量「未命名」日记一次性修复指引（票 02 配套 · 2026-09-16）

## 背景：占位标题是怎么来的

2026-09-16 之前，`writeDiaryCore` 的标题派生是「显式 `title` 参数 > 正文首个 `# ` 标题行 >
`${date} 未命名` 兜底」。只要正文没写 `# ` 标题行、又没显式传 `title`，就会自动落
`# YYYY-MM-DD 未命名` 占位标题——`memo_write` 与 `memo_update` 都中招。

库内标题是**强检索信号**：注入块的 `D<n>「标题」` 展示、`memo_update`/`memo_merge` 的标题定位、
近因判据的标题日期回退、使用台账的可读性，全都吃它。占位标题等于把这篇记忆的「地址」抹掉。

实锤样本：
- genshin-ts 桶「2026-09-15 未命名」（T03 精读批2，129 条硬规则——合格正文被废标题拖累）；
- 2026-09-16 dsh-memo-river 桶 `memo_update` 活体复现：新正文无 `# ` 行 → 库内标题从有效值
  降级为「未命名」（文件名保留，库内标题受损）。

## 现状：票 02 之后的口径

- **派生链**：显式 `title` 参数 > 正文首个 `# ` 标题行 > 改写/合并目标的原标题；三级皆无 →
  `missing-title` 明确拒绝（错误文案指引补标题），**不再静默落「未命名」**。
- **重复拼接修复**：标题取自正文 `# ` 行时，该行从写盘全文中剥掉（旧版模板再拼一次导致标题行出现两次）。
- **改写不降级**：`memo_update` 新正文无 `# ` 行时保留目标原标题；`memo_merge` keep 模式同口径。
- **残次品不保底**：改写目标原标题本身是「未命名」占位（`YYYY-MM-DD 未命名` / 裸「未命名」）时，
  闸门拒绝续命——必须在新正文首行给 `# 新标题`。

## 排查（只读，不动生产桶）

1. 逐桶看清单：`memo_stats`（标题 = chunk `#` 首行）。
2. 直接查库（sqlite3 **只读 SELECT**；禁止任何写操作）：

```sh
for db in ~/.dsh/memo-river/*/knowledge_base.sqlite; do
  echo "== $db"
  sqlite3 "file:$db?mode=ro" \
    "SELECT id, diary_name, path FROM files WHERE path LIKE '%未命名%';"
done
```

（占位标题同时落在 chunk 首行与文件名 slug 里，两条口径都扫更稳：`path LIKE` 之外，
可再对 chunks 表 `content LIKE '#%未命名%'` 查一遍。）

## 一次性修复（逐篇手动，不批量自动改）

标题需要人来起——自动改写只会把一个占位符换成另一个占位符。对每一篇：

```
memo_update(
  id      = <D 编号>,                  # memo_stats / 上面的 sqlite 查询拿到 file id
  content = "# <起好的新标题>\n\n<原正文，去掉旧的未命名标题行>\n\nTag: <原 Tag 行>"
)
```

要点：
- 原正文从 `memo_recall` 或库内 chunk 取回；
- 新标题应概括这篇**真正记了什么**（典型样本就是正文首句本来就该当标题）；
- 路径/文件名不会随之更改（路径即身份，保留是对的）；改的只是库内标题与写盘全文；
- 修完用 `memo_stats` 复核该篇标题已更新。

验收入口：`node scripts/acceptance-title-gate.mjs`（T-5 判据即本指引的活体复现——
改写「未命名」存量条目被拒、补 `# 新标题` 后放行）。
