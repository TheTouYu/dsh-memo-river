## 0. 一句话

> **工作时绝不打扰，只默默记下"这次哪几条记忆真的被用上了"。等它安静下来（压缩后／汇报后／无指令的自主步），
> 把这几条的**关键正文并排摊开**摆到它面前，问一句：这几条是不是可以合起来变成一条更好的？**

三个词：**只记录 → 安静时才提 → 成组（不只单条）**。

## 1. 要解决什么问题

记忆写下来之后会**慢慢变旧**，但**没有任何人去修正它**。用户原话（2026-10-15）：

> 「随着时间的推移，原来的写下的记忆，可能会不对，但是没有去修正它。这个应该怎么做工程实践？」

### 1.1 为什么四条"看起来对"的通道不成立（已否决，别再提）

| 被否决的方案 | 为什么不成立 |
|---|---|
| 全库事实核验巡检（抽路径/端口/配置键去逐个验） | **要求模型去做一件事**——模型只在"被提醒且代价极低"时才动手，主动发起流程不会发生 |
| 用时核验（召回时顺手验） | 同上；且拖慢注入路径 |
| 冲突检出（两条互相矛盾的自动报） | 判"谁对"很容易错；且仍是要模型执行的流程 |
| 写入时声明依赖 | 最准但最贵，属写侧额外契约，模型不会稳定执行 |

**结论（用户 2026-10-15 拍板）**：不做复杂实现、不强制模型做很多事，**只做一个机制：在自然的时候提醒它"稍稍回忆一下、可以更好"**。

### 1.2 与 G3 的关系

- **G3 = 显式取代**：有人当场声明，或事后有人发现并标记 → 已落地（`memo_supersessions` + `memo_supersede`）。
- **本 spec = 隐式演化**：没人知道它旧了，靠"被用过"这件事把它自己推到台面上。

## 2. 三条根本认识（推导过程，别丢）

### 认识一：重组的瞬间不是"看代码时"，是"刚为了同一件事翻了三处"的那一瞬

"重大影响"的可观测形式**不是"被召回"**（拿到 ≠ 起作用），而是：
**为了做完这一件事，它把这几条凑在一起用了。**

→ **这几条一起出现，本身就是"它们该合并"的信号。**
→ 这个信号**不需要相似度**。本仓早有教训（D79）：**余弦测不出叙事冗余**（"Everything is done"残渣五连两两余弦都不高，却是同一件事被写了五遍）。而"被同一次思考一起用上"正是"叙事相关"的机器可观测代理。
→ **分组依据不用发明，它是免费的。**

### 认识二：人不在工作时整理记忆，是睡着时

"安静"不能只是"任务做完了"，要有一个**与当前任务无关的时段**。我们已有三个现成的安静时刻（**零新增时机探测**）：

| 安静时刻 | 为什么它天然 | 现有信号 |
|---|---|---|
| **压缩刚发生之后** | 那一刻它**刚把一段热的经历折成冷的摘要**——已经在做"提炼"，顺手整理记忆边际成本 ≈ 0。且压后正是记忆最脆弱的时刻（旧注入块被折进摘要） | `compactionFired`（已存在） |
| **一次实质汇报刚结束** | 写节律提醒已实测证明这是最佳投递点 | write-nudge 判据（已存在） |
| **无用户指令的自主步** | 它在自己推进，没有外部任务压着 | `isTurnStart === false`（已存在） |

**优先级：压缩后 ＞ 汇报后 ＞ 自主步。**

### 认识三：不要从外部推断"影响"，让"被用上"自己留痕

采集与优化**分开**：
- **采集（工作时，极轻）**：注进去的那几条里，哪些的**独有内容**出现在了模型这一轮正文里 → 记一次"用上了"
- **优化（只安静时）**：安静时从**这个池子**里挑，而不是从全库挑

→ **"哪条重要"不是判断出来的，是被用出来的。**

## 3. 结构洞察：不新建提醒通道

写日记提醒（write-nudge）已经在**同一个安静时刻**让模型动手改语料。新机制落在**同一时刻、同一动作**上：

> 写 = 把新的加进去；复查 = 把旧的整理好。**同一个动作的两个方向。**

**所以并进既有收尾提醒，不做第二条通道。** 理由：
- 模型**已经建立**"收尾时动手写日记"的习惯（实测 0/30 自发写入，靠提醒稳定下来 —— D142）
- 我们不要求它养成新习惯，只在同一个习惯里多给一件事
- 工程上：**零新增投递通道、零仲裁逻辑**（否则两条提醒抢同一时刻）

## 4. 已定口径（用户 2026-10-15 逐条拍板）

| # | 决定 | 出处/理由 |
|---|---|---|
| D-1 | 一次**最多提 5 条**，并**明确告诉模型"这只是候选，你要做更多也行"** | 机制给材料，范围由模型自己定 |
| D-2 | 动作四项：**合并（`memo_merge`）排第一**、**新增（`memo_write`）**、改写（`memo_update`）、取代/废止（`memo_supersede`） | 合并才是"进化"，其余是"修理"；新增补上"这一组的知识其实该重新写成一条"的情形 |

| D-5 | 提示形态 = **证据板**：**把回忆的关键正文并排摊开**，不是"摘要+建议" | 见 §5.5，用户 2026-10-15 纠正 |
| D-6 | **绝不做成 KPI**：不催第二次、不积欠账、不算"复查率"、不做排行榜 | D93「机械批准」污染语料的前科——为交差而改比不改更糟 |

## 5. 工程细节

### 5.1 采集：怎么判"这次真的用上了"

**判据（待实验冻结）**：这一轮**模型的正文**里出现了某条记忆的**独有内容**。
"独有内容" = 它独有的数字、路径、标识符、罕见词。**不是标题词，不是 Tag。**

**三道假阳性防线**：
1. **IDF 过滤**——该 token 在库里普遍出现 → 不算（D106 用过：防"预设组合器"这类项目名词假阳性）
2. **同轮其他来源排他**——该 token 在**本轮工具输出/用户消息**里也出现 → 不算（否则把工具输出当成"用了记忆"）
3. **排除标题与 Tag 词**——它们会原样出现在别处

**回溯时机**：正文在**这一轮结束**才有 → 采集是对**上一轮**的回溯判定，发生在**下一步开始时**（D106 同款口径：10 分钟窗）。

**偏严优先**：假阳性的代价是"让模型去优化一条其实没用的记忆"（乱提）；漏采的代价只是"少提几次"。→ **宁少提，不提无关的。**

### 5.2 成组

- **同一回合里被一起用上的条目 = 一组**（最干净的"被同一次思考一起用上"）
- 相邻回合连续用上的 → 用**滚动窗口**并进同一组（避免一件事被切碎）
- 组上限 5 条（与提醒上限一致）
- **组内 ≥2 条才有"合并"意义；只有 1 条 = 单条打磨场景**——同一机制，特例不另写

### 5.3 安静时刻

三锚（§2 认识二）+ **每回合 ≤1 次** + **冷却 20 分钟（上限）**。

**必须写进机制的规则**：**如果这个会话从没安静过（长任务连轴转），就永远不提。**
—— 宁可不提，也不打扰。

### 5.4 选材

- **池子** = **本会话被用上的条目**（不是全库——这把范围从几千篇压到个位数）
- **排序**：成组的（≥2 条一起用过）→ 被反复用过的 → 最近用过的
- **排除**：刚被复查/改动过的（`lastReviewedAt` 挡）
- 取 ≤5 条

### 5.5 提示形态（**证据板**，本 spec 的核心产品面）

**反面教材（已被用户否掉）**——我第一版写的是**注解**：

```
D214 写于 30 天前(它引用的 embedTimeoutMs 现为 8000)｜D208 有更新的 D229｜D225/D227/D233 常一起被用
```

**为什么错**：这些都是**我替代模型做的判断**，不是材料。而且——**注解不能并排对比，正文能**。
这些记忆原本**散落在不同轮次的注入块里**；**把它们的正文并排摆在同一处，本身就是新信息**：
只有在并排时，"这几条其实在讲同一件事"才在视觉上成立。注解把这个核心价值丢掉了。

**正确形态**（样例）：

```
[memo-river·收尾] 非新任务：这次你用上了这几条，正文如下 ——

D214「3s 嵌入硬顶」（你回复里用到了「3s」「45.3%」）
  3s 预算贴脸设计，近三日约一半回合因 embed 超时被静默跳过…（实测 skip 45.3%）

D208「例行体检：端点劣化致半数跳过」（你回复里用到了「45.3%」）
  近三日被动召回约一半回合因 embed 超时被静默跳过；端点 RTT 从 ~700ms 抬到 ~3s+…

D225「条目级注入去重」（你回复里用到了「集合级」「整块重注」）
  集合级判据只在入选集合完全不变时跳过；集合一变，A、B 被整块重注…

可合并成一条(memo_merge)／写一条新的(memo_write)／改写(memo_update)／取代或废止(memo_supersede)。
有更准更短更清楚的改法就顺手改；没有真实改进就不动。要做更多也行——这只是候选。
```

两条随之定下的纪律：
1. **每条给「结论句 + 独有事实」**，不是首句、不是全文（首句常是叙事铺垫，不是判断材料）；
2. **宁可少提几条，也不把正文压成注解**——放不下就少提，倒退成注解 = 退回被否掉的那版。

**字符预算（待实测定）**：5 条正文 ≈ 500–700 字；上限建议 **≤600 字**，超了**减条数**。
末两句是**授权句**（你自己决定范围）+ **许可句**（没有真实改进就不动），**缺一不可**。

### 5.6 存储（零新建表）

| 数据 | 放哪 | 生命周期 |
|---|---|---|
| 本轮用上了哪些 / 组 | `SessionState`（进程内） | 会话内有效，丢了无所谓 |
| 最近复查过哪些 | 复用**使用台账**那一个 kv，加 `lastReviewedAt` | 长期足迹 |

使用台账现状（已核实）：`UsageEntry = { passive, active, lastPassiveAt, lastActiveAt }` —— 主动/被动分开且带时间戳，
`recordUsage()` 写入、`readUsageLedger()` 读（`src/health.ts:153/174`）。**"今天回忆出来的知识"现成可查。**

### 5.7 通道

并进既有收尾提醒（§3），与 write-nudge 共用投递时机与冷却。**不新增 nudge 类型。**

### 5.8 动作 → 工具映射（命令形状直接写在提示里）

| 提示里的动作 | 工具 | 备注 |
|---|---|---|
| 合并成一条 | `memo_merge` | **排第一**（进化）；自带 archive 归档与溯源行 |
| 写一条新的 | `memo_write` | 把这一组的知识重写成一条更抽象的结论 |
| 改写 | `memo_update` | 同 fileId 原地重写，台账足迹保留 |
| 取代/废止 | `memo_supersede` | G3 的工具，直接复用 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 模型为响应而做**低质量改动**（D93 前科） | 改动仍走**全部既有闸门**（Tag 同义 / 近重复 0.95 / 标题 / hub）；提示里明确"没有真实改进就不动" |
| **过度改写**把好记忆改坏 | 观测**反向指标**：改动是否被后续去重闸门拒（被拒 = 改出了冗余） |
| 提醒**占上下文** | 字符硬上限（§5.5）；20 分钟是上限不是节拍；无新痕迹不提 |
| 变成 KPI 后**为交差乱改** | D-6：不催第二次、不积欠账、不算率、不排行——写进机制 |
| **从没安静过**的长任务被打扰 | §5.3：永不提 |

## 7. 实验方案（**先做这个，判据未冻结前不写生产代码**）

### 7.1 要回答的唯一问题

> 在真实会话里，**哪一种判据**既能抓到"真用上了"，又不会把**工具输出里的同一个数字**误当成"用了记忆"。

### 7.2 语料（现成，零生产改动、零端点依赖）

| 素材 | 位置 |
|---|---|
| 注入事实（哪轮注了哪几条） | `~/.dsh/memo-river/*/memo-river.log` 的 `inject … ids=D…` 行（带 session id 与时间戳） |
| 模型正文 | `~/.dsh/sessions/--home-h-dsh-plugins-dsh-memo-river--/*/session.v3.jsonl.zstd` 的助手正文 |
| 被注入条目正文 | 各桶 `knowledge_base.sqlite` 的 `chunks.content` |

**对齐**：一次 `inject` 行 → 其后该 session 的第一段实质助手正文（10 分钟窗口径，D106 同款）。

### 7.3 四组判据 A/B（同一语料，同一把尺）

| 代号 | 判据 | 特点 |
|---|---|---|
| **J1 严格** | 独有 token ∩ 正文，**且排除同轮工具输出/用户消息** | 偏严，漏采多 |
| **J2 宽松** | 只排除标题词与 Tag 词 | 偏松，假阳性多 |
| **J3 片段级** | 正文里出现该条**连续片段**（长度 ≥ N 字） | 抓"把这句话搬过去了"；**天然给连续量** |
| **J4 结构化** | 模型**工具调用参数**里出现该条的值 | 抓"影响了动作"，不停留在嘴上 |

**J3 最被看好**：给出的是"最长公共片段长度"这个**连续量**，不必拍阈值。

### 7.4 怎么算"判对"

1. 脚本输出每轮 `(注入了哪几条, 各判据命中哪几条, 命中证据串)`
2. 抽小样本（≈50 轮）**由在场者判真伪**（本仓规矩：在场者判断）
3. 算 **precision / recall**；按 §5.1 原则 **假阳性必须低、漏采可接受**
4. **阈值定法**：看 J3 连续量的**分布是否双峰**——双峰说明"真用了"与"碰巧"可分，阈值落谷底；**单峰说明判据不好用，换判据**（不许硬拍阈值）

### 7.5 产出与副产品

- 产出：**冻结的判据 + 阈值**（回写本 spec §5.1）
- 副产品（一石二鸟）：**「注入 → 被采用率」常驻读数** —— 这正是长期三变量③缺的那个缺口（此前只有 D106 手工测过一次 66%）

### 7.6 脚本形态

`scripts/probe-injection-adoption.mjs`：**只读**、可重复跑、不碰生产（与既有 `probe-*` 同名族）。

## 8. 验收（待实验数据回来后补全）

实现完成后至少要能回答：
1. 安静时刻**真的**触发了多少轮（触发率）
2. 提了之后 **N 步内是否发生** `memo_write/update/merge/supersede`（采纳率）
3. **语料走势**：条数 / 平均长度 / 陈旧条数的变化 ← 最终判据
4. **反向指标**：改动是否被后续去重闸门拒（拒 = 改出冗余 = 机制在制造噪音）

**以上四条只作读数，不作考核**（D-6）。
