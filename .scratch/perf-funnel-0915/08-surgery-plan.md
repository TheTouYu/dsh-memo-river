### 2.3 新 Tag：`误判翻案`（唯一新词）

- **newTagReason**：六篇（D13/D28/D29/D38/D39/D75）共享的叙事结构是「我下了判断 → 对照实验/磁盘证据推翻它 → 教训」，语义是**自省翻案事件**；现有 `结论的成立条件` 表达的是认识论条件（什么条件下结论成立），`测量纪律` 表达的是测量方法约束——两者都装不下「翻案」这一事件类型，强行复用正是本桶枢纽化的成因。
- **风险与 fallback**：若闸门拒新词，fallback = 六篇改为「只摘不补」（如 D38 保留原三词），`结论的成立条件` 需另寻 −1（候补：D43 或 keeper G7/D84 摘词），重跑模拟器验证 ≤16 后再执行。

## 5. 回滚说明

### 5.1 术前快照（每桶必做，这是唯一完整回滚通道）

```bash
H=<桶hash>
# 全量文件快照（含 sqlite + wal/shm + emb-cache + dailynote + pending）
tar czf ~/memo-river-backup-${H}-$(date +%Y%m%d-%H%M).tgz -C ~/.dsh/memo-river ${H}/
# 库级一致快照（daemon 在写时更稳）
sqlite3 ~/.dsh/memo-river/${H}/knowledge_base.sqlite ".backup /tmp/kb-${H}-$(date +%Y%m%d-%H%M).sqlite"
```

### 5.2 各类动作的回滚通道

- **retag（memo_update）**：原地重写磁盘 .md + 库内同路径 upsert，fileId/使用台账足迹不变。回滚 = 对目标篇再做一次 memo_update，把 Tag 行改回台账记录的旧行（§7 台账逐篇记录旧值）。正文未动，无需库恢复。
- **merge（memo_merge keep 模式）**：源篇 .md/.txt 已移入桶根 `archive/`（`src/tools.ts:912`，人可读、保留原 Tag 行），但**库内 files/file_tags/chunks 行已清除**——没有半自动恢复通道。回滚 = 停止写入 → 用 §5.1 的 sqlite .backup 覆盖 knowledge_base.sqlite（同时清掉 -wal/-shm）→ dailynote 从 tar 恢复 → 守护下一轮自动重建派生资产（tagmemo/rivermemo artifacts 按 artifactSig 重算）。
- **全桶灾难**：tar 整桶覆盖，同上。
- ⚠️ 回滚窗口建议：术后 48h 内保留快照（覆盖两轮守护体检 + 一轮真实使用）；确认冒烟全过、体检转绿后再删。
