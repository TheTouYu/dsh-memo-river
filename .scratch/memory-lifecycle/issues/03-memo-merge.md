# 03 — memo_merge：多篇归一与归档退役

**What to build:** agent 能把多篇旧日记合并成一篇：给出源篇 id 列表与合并后内容；源篇 `.md` 移入 `archive/` 子目录（人可读、保留原 Tag 行），库内行级联退役（chunks/file_tags 随之外清）；合并篇入库——新篇走 `memo_write` 路径，或并入既有篇走 `memo_update` 的 upsert；合并内容**仅对声明的源篇**豁免去重闸门；正文自动落「合并自 D…, D…」溯源行。合并后召回只命中合并篇。这是「压缩式遗忘」的执行通道：600 token 注入预算下，语料变瘦变响亮。

**Blocked by:** 02 — memo_update（复用其 upsert 与闸门自排除机制）

**Status:** done — 2026-09-14（acceptance-merge.mjs 6/6；回归 update 7/7 / usage 6/6×2 / 主套件 30/31，唯一红 #29 属并行会话在制票01+05 / P3 4/4）

**实现附记：**
1. 两模式：缺省 = 新篇模式（全部源归档，符合判据「archive 留 2 源」）；`keep=D-id` = 并入模式（保留篇 upsert，身份/台账足迹延续）。
2. 归档双侧：磁盘移 archive/（工作区根外的源**复制归档、原文件不动**，同票②护栏）；库内 chunks/file_tags/files 行删除；使用台账同步清扫源篇条目。
3. 溯源行 `> 合并自 D…（日期 退役归档）` 自动插入 Tag 行前；D-id 复用风险（无 AUTOINCREMENT）已在 DESIGN 记为以 archive/ 原文为准。
