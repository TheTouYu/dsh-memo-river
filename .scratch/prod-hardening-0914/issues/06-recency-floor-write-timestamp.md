# 06 — 近因保底改用写入时间戳（同日并列短路修复）

**What to build:** 近因保底真正保住「最近写入的日记」，而不是「标题日期最新那一天里分数最高的一篇」。2026-09-14 生产实锤（recall 选集环节）：并行会话 11:23:56 写入 D19（遗忘与强化判定），11:27:05 压缩联动注入时 D19 落选——保底判据用标题解析日期，只有**天**粒度；同日平局时按分数序取，已入选的同日日记 D18 被当作 "freshest"，`未入选` 检查短路，整条保底失效，3 分钟前最相关的 D19 永远进不来。

**修法**：保底的"新鲜度"判据从标题日期改为**写入时间戳**（存储层已有）；时间戳不可得时退回标题日期；同刻平局取最新写入者。保底其余语义不变（挤分数最低席、不动 top1、≥2 席才启动、预算不够走首句截断）。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent
