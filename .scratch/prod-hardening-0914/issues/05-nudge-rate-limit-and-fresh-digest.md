# 05 — write-nudge 限流与弹药刷新（连拍修复 + digest 现取）

**What to build:** 写入节律提醒在工具大输出阶段不再连拍，且每次提醒携带的是当下战况而非上回合存货。2026-09-14 生产实测：preset-composer 会话 11:04:48/11:06:36/11:08:48 三发间隔 90 秒-2 分钟——增量锚把浏览器 DOM dump 全额计入「进展」，50K 字符几分钟攒满反复触发；且 digest 来自上一回合 turn-stopping 的陈旧摘要（实测收到引用旧战况的提醒）。

**三项行为（用户拍板口径）**：
1. **增量锚工具输出封顶**：统计增量时，单次工具输出的计入股 = min(实际长度, 本会话截尾均值上限)。上限取值 = 本会话最近 N 次工具输出长度的**截尾均值**（去掉最高 10% 与最低 10% 后取平均；样本不足时用保守默认上限，首次采样前不因工具输出触发）。助手产出字符不封顶。
2. **最小重发间隔**：两次 write-nudge 之间强制 ≥5 分钟，任何锚都不豁免（issue #108 教训：正反馈连拍）。
3. **digest 现取**：触发时从最近一条助手实质文本现取摘要，不使用 turn-stopping 存货；取不到时退回自主态通用文案。

**Blocked by:** None — can start immediately（与 01 协同：01 的遥测落盘让本票效果可生产验证，但验收可离线完成）。
